# spark-threshold-vouch · 担保链门槛（示例）

C11 门槛插件参考实现（担保链，**组织空间**）：被担保人发起请求，N 名已有
参与者担保，收齐后组装「是否满足门槛」的签名证明（ThresholdProof）。对齐
wiki/architecture/community-affairs.md §7.3：门槛插件产出产物，内核/事务
客户端只验证产物，不执行担保流程。

担保流程天然跨主体（请求者、N 个担保人是不同的人），故 manifest
`supportedSpaces: ["org"]`——三个集合随组织同步面流动，担保人作为组织
成员在同一数据面上写入。治理上下文 `context` 为受限词法
`affair:<事务id>` / `org:<组织id>`（插件侧只校验词法，存在性校验需
事务/组织读面，当前未引入以免扩大权限面）。

## 能力面与权限

- `docs`：请求/担保/证明三个 append-only 集合（storage:read/write）。
- `identity:sign`：担保与组装签名（高级权限）。
- `identity.verify`：证明产物的免权限验签（基础权限）。

## 诚实口径（务必先读）

本插件是**演示级**参考实现：**所有担保与组装签名的主体都是插件域身份**
（`plugin:spark-threshold-vouch` 域私钥）。平台 SDK 只有 `identity:sign`
（插件域签名面），插件拿不到用户个人身份签名能力——因此：

- 签名在密码学上**不证明担保人/组装人的个人身份**；`assembledBy` 是自报
  文本，`voucherRootId` 取自担保操作者的本机当前根身份
  （`sdk.runtime.currentRoot()`），同样只是展示字段、无密码学绑定；
- 「免权限验签」验的是**插件域签名有效 + 载荷未被改动**（任何节点对同一
  证明得到同一结论），而不是「担保人本人签过」。

**担保人防伪加固（演示线形内的真实强度）**：担保人身份不接受手填——担保
操作自动以当前身份签名，门槛计数与去重一律按**担保签名公钥**。插件域身份
按（根身份 × 域串）派生，不同根身份 ⇒ 不同域公钥，因此「N 份不同公钥的
担保」≈「N 个不同 Spark 根身份担保」：一人签 N 份只计一次，伪造担保人
rootId 文本在计数层不成立。残余口径：同一根身份在多台设备上派生的域公钥
是否恒定取决于平台域身份口径（未冻结），多设备同人可能贡献多把公钥。

在平台层提供个人身份签名路径之前，本插件的 ThresholdProof 不得被当作
「N 个具体个人担保」的证据使用；届时应以个人身份签名路径重做担保签发。
