# Spark 文档体系总纲（code/docs）

> 本目录是 Spark 的**目标文档与权威定稿**：产品说明书、目标架构、界面设计、已定稿协议规格、各类规范，以及用户/开发者文档。
> **现状与过程记录在 wiki/**：实现记录、fix 链、评审打回、发版记录、排障案例、已被取代的旧草案存档。
> AI 协作者在本目录工作前，还须读 [ai.md](ai.md)（wiki→docs 迁移规范）。

---

## 一、两个文档体系的分工

| | `code/docs/`（本目录） | `wiki/` |
| --- | --- | --- |
| 回答 | 目标是什么、规则是什么、规范是什么（权威） | 现状是什么、过程发生了什么（记录） |
| 成色 | 定稿，稳定，改动须经讨论拍板 | 快速迭代，含大量过程稿与历史草案 |
| 生命周期 | 随代码仓库版本演进，随提交评审 | 随工作实时回写，可自由增删 |

**冲突仲裁**：目标与规则以本目录为准；实现现状以 wiki / 代码为准。二者不一致时，在本目录相关篇目"现状 → 差距"节如实呈现，不回改产品权威（product 变更只能经用户拍板）。

**迁移规则（一处事实一处权威）**：wiki 中"已实现且已稳定"的内容（典型：协议线形规格、测试体系、编码规范）迁入本目录对应区后，wiki 原文删除、引用更新，不留跳转空壳，不两边各存一份。

## 二、目录职责

| 目录 | 装什么 | 不装什么 |
| --- | --- | --- |
| `product/` | 产品说明书：是什么、为什么、规则与边界（产品权威） | 实现细节、协议字段 |
| `architecture/` | 目标架构与迁移设计：怎么做、现状→差距→目标→迁移路径 | 需求定义、字节级规格 |
| `ui/` | 界面设计：信息架构、外壳、交互与视觉决策 | 系统架构、后端协议 |
| `protocol/` | **已定稿**的线形规格：wire format、存储键、签名/信封格式、golden vectors 登记 | 设计动机（归 architecture）、未实现的设想 |
| `testing/` | 测试体系与方法规范：分几层、怎么写、覆盖清单 | 测试执行记录、验收报告（归 wiki） |
| `security/` | 威胁模型、安全规范、密码学使用约定 | 安全评审报告（归 wiki） |
| `dev/` | 开发者文档：环境搭建、构建、编码规范、**如何开发插件** | 体系设计（归 architecture） |
| `user/` | 用户文档：安装、使用手册、FAQ | 一切工程内容 |
| `ai.md` | AI 协作规范：wiki→docs 迁移纪律 | — |

**记录类内容不进本目录**：评审记录、排障案例、发版记录、测试报告——它们回答"发生了什么"，永远归 wiki。

## 三、归属裁决规则（按优先级）

1. **内容主体决定归属**：以 80% 以上篇幅涉及的内容类型为准，不因附带一两段其他类型内容而改归属。
2. **"做什么" vs "怎么做"**：做什么、为什么 → `product/`；怎么做、放哪层、动哪些模块 → `architecture/`。
3. **协议 vs 实现**：线形字段、存储键、签名格式 → `protocol/`；上述协议的设计动机、方案选型 → `architecture/`。
4. **规范 vs 记录**：怎么做才对（规范）→ 本目录；做了什么、发生了什么（记录）→ wiki。
5. **读者是谁**：面向最终用户的操作说明 → `user/`；面向开发者的工程说明 → `dev/`。例：「如何开发一个插件」→ `dev/`；「插件体系如何设计」→ `architecture/`。

边界不清时，在文档开头用一行标注协作方，以主体所在区放置：

```markdown
> 协作方：本文档以协议规格为主，设计动机部分与系统架构师对齐（见 architecture/ 对应篇）。
```

## 四、写作约定

1. **状态标注**：文首标「草稿 / 定稿」；定稿的改动须经讨论拍板。
2. **一处事实一处权威**：一个事实只在一篇权威定义，其余地方链接；改权威处时同步检查引用处口径。
3. **命名**：小写英文 + 连字符（`personal-data-sync.md`）；每目录一个 `README.md` 做入口与索引（列每篇一句话说明）。
4. **编码**：UTF-8 无 BOM。
5. **粒度**：一篇一主题；`##` 超过 7 个或超过 300 行，考虑拆分；拆分后留 README 索引。
6. **互链**：
   - 本目录内部一律用相对路径；
   - 引用 wiki 篇目用「区 + 篇名」文字（如 `wiki protocol/org-join`）或完整 GitHub Wiki URL，**不用跨仓库相对路径**；
   - wiki 侧引用本目录，写「code 仓库 `docs/...`」。
