# 架构设计：法币关系与合规（为什么这一篇几乎没有内核工作）

> 模板：产品目标 → 现状 → 差距 → 目标设计 → 迁移路径 → 验收。对应产品文档：[../../product/economy/fiat-compliance.md](../../product/economy/fiat-compliance.md)（定稿）。

## 一、产品目标（来自 product/economy/fiat-compliance.md）

1. 不隔离法币：组织可登记为合法市场主体、对外经营、依法纳税；
2. 防收编四闸门：① 不开对私兑现通道（**结构封死**）；② 不挂汇率、③ 法币收入归集体、④ 价值落在网络内真实资源（②③④ = 纪律 + 留痕，**软件无强制力**，对外材料不得宣称"软件能防法币私分"）；
3. 顺差三去向 = 组织章程纪律（留痕可对照）；
4. 合规边界：不过手法币、不设资金池、不做公众清算；积分非工资；涉税视同销售口径留专业意见，存证链提供完整凭证留存；
5. **资本结构三层论**：信息面可映射（插件记账）、结算面在系统外（银行）、权力面 = 内核经济对象封死 + 插件资本数据组织自选（契约快照通道）。

## 二、现状（核实日期：2026-09-08）

经济代码为零（绿地），现状无经济协议可言——闸门 1 的结构封死是**目标设计属性**（证明落在 credits / inter-org 线形与 §六负向测试）。已建成的基础：存证链（法账对照留痕的基础）；插件体系（经营账记账的载体，declareCollection）。

## 三、差距

| # | 差距 | 说明 |

| G1 | 经营账 / 法币留痕插件不存在（模板层） | 归插件，非内核 |

## 四、目标设计（全部是"不做什么"的落点 + 插件侧）

1. **结构封死清单（验收用）**：① 积分状态机无"兑现"迁移（credits 篇 types.rs 证明）；② 往来账只记积分与资源，无货币字段（inter-org 篇线形证明）；③ 协议无 fee / 资金池 / 公众清算字段；④ 票权求值不读积分余额（governance 篇 §4.5 求值输入白名单证明）；
2. **经营账插件（模板层，catalog 候选）**：组织可选装——记录法币收支、与积分账物理分账（两个数据域、两个决策程序）；分配决议走事务（留痕）；**该插件是"信息留痕"工具，内核不为其提供任何法币通道**；
3. **三层论的架构落点**：股权 / 出资 / 分红 = 插件集合数据（信息面）；治理策略若要引用，只能经契约发布物快照（plugin-types 篇 §4.2），且内核经济对象（积分 / 债权）永远不得作为票权输入（rules 输入白名单强制）；结算永远走银行（系统外）；
4. **合规留存**：对外经营凭证（合同 / 发票 / 决议）按组织数据面存档 + 存证锚；需要时经导出包（evidence 篇）提供给税务 / 法律程序——"视同销售"等口径取得专业意见后由插件模板声明，内核无税务概念。

## 五、迁移路径

无（本篇无内核交付物）。经营账插件纳入模板层候选清单（catalog 现无此条目；catalog 属 product 层，登记需提请用户拍板，A40 跟踪）。

## 六、验收

- **结构封死证明（负向测试）**：尝试构造"积分兑现法币"操作类型 → 编译期不存在；构造票权求值输入含积分余额 → rules 校验拒绝；
- **插件侧**：经营账插件数据域与积分域隔离测试；分配决议留痕可经导出包核验；
- **文档验收**：对外材料审查清单（不得出现"软件防止法币私分 / 保证顺差用途"话术）随本篇归档。
