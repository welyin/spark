# 架构设计：跨组织受理（双边协议、往来账与清算）

> 模板：产品目标 → 现状 → 差距 → 目标设计 → 迁移路径 → 验收。对应产品文档：[../../product/economy/inter-org.md](../../product/economy/inter-org.md)（定稿）。**排期注记：本篇为里程碑二之后的后段设计**（Q13：前两个里程碑只做单组织闭环）。

## 一、产品目标（来自 product/economy/inter-org.md）

1. **相互受理，不是货币兑换**（四方模式）：个人永远只持本组织积分；消费当场核销回发行方，受理方记应收，发行方记应付；Spark 只传凭证、套算、记账、见证——**不垫券、不持仓、不做交易对手**；
2. 往来账双向对冲，**净额定期以真实资源平仓**（不用法币、不展期、严禁借新还旧）；每条双边协议必有**双向净应收上限**，到顶暂停受理；协议解除有状态机（已签名净额不可单方否认）；
3. **实报实销**：跨组织消费必须当场在线完成发行方确认与核销（发行方不可达即失败；在线两阶段：锁定 → 交付 → 销毁落账；可用性是发行组织自己的责任）；
4. 不产生行情（无订单簿 / 不撮合 / 无成交均价）；路径汇率 = 双边合同条款的确定性套算；签约经双方各自按自声明策略的决议（公示延迟）；
5. 消费隐私信息分割（核销指令 vs 交付清单分开；内容不回流发行方、不入网络账本；对内记名以记账组织为界，记账主体自选）；
6. v1 直接双边，v2 代理受理链（"信息沿链传、信用不沿链传"、成对零净往来账、原子交割、**无路由费**——协议无 fee 字段；横跳 / 层跳双预算）；
7. 网络准入只设强制披露（规则三级公开 + 健康度），不做内容审查；自由的代价是自担孤立。

## 二、现状（核实日期：2026-09-08）

代码为零（经济内核未建，credits 篇为本篇前置）。可复用资产：org-mail 网关邮箱（核销凭证送达）、组织网关活跃集（network 篇 §4.2）、存证链（往来账与平仓存证）、policy 引擎（受理入口确定性拦截）、定点数 `fixed.rs`（credits 篇 §4.5）、母稿 §4 / §9（四方账目、两阶段、协议解除、取整算法底稿——注意"网关受限授权密钥复用 orgkey-acl"已随 C7 失效，需以组织签名包 OrgSigSet 替代）。

## 四、目标设计

### 4.1 线形与四方账（`economy/agreements.rs` / `ledger.rs`）

```jsonc
// 双边协议（组织级对象，双方各自决议签署，公示延迟）
{ "agreementId": "<64hex>", "aOrg": "org_<…>", "dOrg": "org_<…>",
  "rate": { "num": 3, "den": 2 },          // 汇率整数比（D 资源 : A 积分）
  "creditCaps": { "aToD": 500000, "dToA": 500000 },  // 双向净应收上限（刻度整数）
  "settlePeriodMs": 2592000000, "pathRadius": { "hop": 2, "layer": 4 },
  "state": "active|cooling|settled|archived" }
// 消费单（核销指令，发行方签名）
{ "orderId": "<64hex 幂等号>", "agreementId": "…", "buyer": "<64hex>",
  "amount": 12500, "lockTs": "…", "nonce": "…" }
// 往来账（append-only，双方互见——账条双签后经 org-mail / 双边直连互换，各自存档）
{ "agreementId": "…", "seq": 41, "delta": +12500, "ref": "orderId",
  "balanceAfter": -37500, "sigA": "…", "sigD": "…" }
```

- **两阶段实报实销**：① 买家向发行方请求核销 → 发行方在线核验余额、锁定并签核销凭证（`held→locked`）；② 受理方验凭证（签名 + 额度未触顶 + 锁版本）→ 交付 → 销毁落往来账（双方签账条）；任一步失败 / 超时整体回滚；发行方不可达 = 直接失败（无脱机赊账）；
- **额度原子扣减**：净应收"检查—扣减"原子串行，并发触顶按先到先得确定性拒绝；锁单即锁版本（事后改约不溯及在途）；消费单 nonce 幂等（重放去重）；
- **griefing 防护**：单笔 / 单邻锁定上限、锁定时长硬顶（超时自动释放）、锁定超时率降被选径优先级、禁止无真实消费单的空锁；
- **失败原因码确定**：无路径 / 触顶 / 发行方不可达 / 超预算 / 余额不足 / 锁冲突。

### 4.2 平仓与协议解除

- **平仓**：到周期对净额以真实资源 / 服务结算（资源目录与折价规则政策层）；平仓登记双方签认入存证；**禁止展期、禁止以券还券**（内核无相应操作类型——结构封死庞氏入口）；
- **解除状态机**：active → 任一方发起 cooling（停接新单、在途单到期完成或回滚）→ 最终净额结算（双方对净额签字）→ archived；**已签名的净额债务不可单方否认**；拒绝平仓 → 该双边额度锁零转争议（挂起原语），不波及其他双边。

### 4.3 汇率与路径（v1 直接双边）

- 汇率 = 协议 `rate` 整数比套算（`fixed.rs` 连乘、末步取整一次、同离散值）；**报价 ≠ 可成交价**：无真实受理边时诚实返回"有理论汇率、无清算路径"并拒绝成交（不得诱导收券）；
- 选径确定性：同一张协议图同一时刻任何节点选出同一条路径（汇率连乘比较用 **u128 交叉相乘判等**——不引浮点对数，与禁浮点纪律一致；tie-break 字典序）；
- **总中转天花板与套利环防护**：横跳默认 2 硬顶 3、层跳 ≤6~8，且**总中转 ≤8**（product 口径，兼作套利环防护）；路径计算**兼作正环 / 异常路径确定性检测**的输入（capital-defense 防线 #9 落点——选径遍历同一协议图，成环与异常路径即图算法副产品，原则句冻结，检测设计随 v2 一并展开）；
- **v2 代理链**（远期，本篇只冻结原则）：四层分离（汇率纯计算 / 交付与体验只有双方 / 账目成对零净 / HTLC 式原子交割）；中间方零净敞口不收费（**协议无 fee 字段**——结构性免费）；横跳 / 层跳 / 总中转三预算并行；网关授权以 **OrgSigSet**（组织签名包）替代母稿的 orgkey-acl 方案。另冻结三条（product 有、本篇登记防丢）：中转权义对等（做种原则）；骨干服务在协议外、服务费不按笔绑定；规模模型两架构不变量（禁全网扇出 / 跨层只传默克尔聚合摘要）+ 状态局部性第一判据。

### 4.4 隐私分割与披露

- 消费单分两半：**核销指令**（买家 / 金额 / 对手方 / 幂等号，发行方签）与**交付清单**（内容明细，买家 ↔ 受理方端到端，不落网络账本）；
- 对内记名以记账组织为界（记账主体自选：只含自己的叶组织也是合法记账主体）；对外假名；
- 网络准入唯一门槛 = 强制披露（规则三级公开 + 持续健康度）；可疑组织不被封禁但无人签约（自担孤立）。

## 五、迁移路径

绿地 + 后段。实施触发条件（**本篇裁定**）：单组织闭环在 ≥2 个真实组织稳定运行后出现首个双边签约需求时启动；届时先落地 agreements / ledger / 两阶段，再平仓与解除，v2 代理链单独立项。

## 六、验收

- **向量**：协议 / 消费单 / 账条线形；两阶段状态机真值表（含发行方不可达、超时回滚、锁版本）；额度原子扣减并发用例；汇率连乘与末步取整同离散值；解除状态机（含否认净额必败）；
- **单测**：幂等重放、griefing 上限、原因码完备性、隐私分割（发行方输入无内容字段）；
- **集成**：两组织四节点 e2e——签协议（双方决议 + 公示延迟）→ 跨组织消费（锁定→交付→销毁落账）→ 净额累计触顶暂停 → 周期平仓签认 → 解除归档；
- **回归**：credits 篇恒等式（跨组织核销回写销毁日志后仍成立）。
