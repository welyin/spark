# 第一层 · 底座（Foundation）：数据、身份、网络、存证

> 状态：定稿
>
> 这一层回答"物"的问题：在**没有任何中心服务器**的前提下，一个人的数据怎么真正属于自己、怎么在自己的设备之间保持一致、怎么在复杂的真实网络里找得到彼此，以及发生过的事怎么被独立证明。

## 这一层在整体中的位置

它是[产品全景](../product-map.md)四层结构的最底层。底座**不认识**组织、事务、积分，也不提供任何业务功能；它只交付四样最基础的东西，上面三层全部建立其上：

| 分册 | 交付的基础能力 | 一句话 |
| --- | --- | --- |
| [personal-data.md](personal-data.md) | 数据属于谁、多设备怎么一致 | 同一人名下的全部数据，在他自己的设备间全量备份式同步 |
| [identity.md](identity.md) | 你是谁、怎么证明是你 | 一个永不暴露的根身份，派生出互不关联的各处身份 |
| [network.md](network.md) | 节点之间怎么连得上 | 能直连就直连，连不上自动中继/暂存，用户无感 |
| [evidence.md](evidence.md) | 发生过的事怎么证明 | 本地链式存证 + 可导出，不装 Spark、不联网也能核验 |

建议阅读顺序同上：**数据是目的，身份是主权，网络是通道，存证是底线。**

## 贯穿这一层的三条承诺

1. **没有服务商。** 不存在一家替你存数据的公司。数据只落在你自己的设备、以及你所在组织授权持有副本的成员设备上；系统里的"服务器"，就是成员家里那台常开的电脑。
2. **零运维。** 穿透、中继、副本、恢复全部自动，目标是"**成员感觉不到网络的存在**"——不需要任何人懂 NAT、端口、服务器。
3. **诚实写明信任边界。** 每一处机制能防什么、防不了什么都对用户讲透，不用"绝对安全 / 永不丢失"的话术。三条必须提前讲明的底线：
   - 中继只搬端到端密文、读不到内容，但**看得见"谁和谁、何时、传了多少"的流量元数据**；
   - 撤销一台设备能阻止它再拿到**新**数据，却抹不掉它此前已经持有的**旧**数据；
   - 去中心化没有"客服重置密码"：**身份**可由助记词离线恢复，但**历史数据**只存在于设备副本上——所有设备同时损毁且无第二副本时，数据无法找回（详见 [personal-data](personal-data.md)）。

## 与上层的接口

- 底座向上只提供"**一个主权个体 + 其可信设备 + 可靠加密通道 + 可证明的历史**"；
- "个人 / 家庭 / 组织"的数据区隔发生在更上层的[共同体模型](../community/model.md)；底座只保证"个人域"这条最内的边界是密封的。

> 工程实现（存储布局、同步协议、密钥派生、libp2p 配置等）见 `wiki/architecture/{sync,identity,p2p}` 与 `docs/protocol/`，本分册只讲产品规则与边界，不复制实现。
