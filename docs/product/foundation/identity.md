# 身份：一个永不暴露的根，派生互不关联的你

> 状态：定稿 ｜ 分册：第一层 · 底座
>
> 上游实现：`wiki/architecture/identity/*`、`docs/protocol/foundation/identity.md`

## 一句话

你只需保管**一个根身份**（由助记词派生的密钥），它永不对外暴露；系统再从它派生出"个人空间身份"和你在**每一个组织里各自独立、互不可关联**的组织身份——**底层保主权，上层保隔离**。

## 三层身份

| 层级 | 用来干什么 | 谁看得到 |
| --- | --- | --- |
| 根身份 root | 密码学根基，派生一切密钥 | 永不暴露，任何插件 / 组织都拿不到 |
| 个人身份 | 昵称、头像、个人签名 | 仅你的个人联系人 |
| 组织身份 | 你在某一个组织里的名字 / 头像 | 仅该组织成员 |

关键产品性质：

- **跨组织不可关联**：你在 A 组织和 B 组织的身份没有可被匹配的共同特征。组织成员无法由组织身份反推你的个人资料，个人联系人也无法知道你加入了哪些组织（默认完全隔离；你可在单个组织内主动选择"使用个人身份"）；
- 组织身份只证明"某成员在该组织内做过此操作"，出了这个域不具意义；
- 业务属性（工号、资质、角色）由组织规则 / 插件定义，内核只做密码学校验，**不定义你是谁**。

## 凭证与备份：双通道，等级不同

- **根身份 = 24 个中文词的助记词**，最高权限、离线兜底，恢复时可重设密码；
- 私钥用你的密码加密后只存本机，永不明网上传、永不在设备间同步；
- **加密二维码备份**：密文形态，可容忍存进相册或经网络传输，但**必须配合原密码**才能恢复——面向普通人换机的主通道。

两者分工必须讲清：

- 记得密码、账号在旧设备还活着 → 扫码迁移最方便；
- 忘了密码 → 二维码解不开（它不是找回密码的手段），只能靠助记词；
- 助记词是纸面最高机密，谁拿到都能拿走账号；明文一旦展示（截图 / 拍照 / 读屏）即永久泄露、无法收回，因此系统从不在屏幕上常驻助记词。

## 登录态、生物识别与高危操作

Spark 没有中心服务器，"登录"不是服务器签发的会话，而是**本机密钥是否已解锁**的本地状态。由此：

- **一次解锁，访问全部已加入组织**：登录只发生在本机这一层，解锁根身份后，你已加入的每个组织都以各自派生的组织身份直接可用，**无需、也不存在"逐个组织登录"**；
- **默认长期登录，不做定时踢人**（与主流 IM 一致；提供可选的"N 天未用自动锁定"，默认关闭）；
- **手机端每 7 天必须输入一次密码**——日常解锁照常刷指纹 / 人脸，但到期必须输一次密码才能继续使用（与主流手机厂商的定期密码验证同款设计）。目的只有一个：不让用户因长期只用生物识别而彻底遗忘密码——在没有客服、没有后门的系统里，忘记密码的代价远高于普通 App；
- **指纹 / 人脸只管日常解锁**；改密码、查看 / 导出助记词这类**高危操作必须输密码**——家人可能录有指纹，"能过指纹"不等于"是账号主人"，否则会形成"指纹改密码 → 新密码导出助记词"的两步夺号；
- **生物特征库一旦变更（新增 / 删除指纹或人脸），保存的解锁密钥立即作废**，强制回退密码验证，防止有人拿到一次解锁后录入自己指纹、获得持久解锁能力；
- 永远不提供"当场刷个指纹就改密码"的即时通道。

## 丢了怎么办：恢复路径与一条诚实的死路

产品上做到"用户只有三种状态、每种状态一扇门、门内不绕"：

1. **有助记词** → 离线恢复并设置新密码（全新设备也可以）；
2. **没助记词、但还有一台已解锁 / 已授权设备** → **延迟恢复通道**：在已解锁设备上用生物识别发起，通知全部已授权设备，进入默认 24 小时延迟期，期间任一设备可否决，到期需**再刷一次**生物识别才生效。它可授权两件事：原地重置密码、无密码配对新设备。设计意图是把攻击成本从"碰一下手机"抬到"持续控制一整天"；查看助记词不走此通道；
3. **以上都没有** → **明确告知账号无法恢复**，不留虚假希望。这是去中心化的固有底线：没有客服、没有后门。

> PC 端没有系统级生物识别门控，"忘记密码"只有助记词一条路；延迟恢复只能在移动设备发起，PC 作为被通知、可否决的一方。

## 改密码：本机重封 + 数据面换锁（不换身份）

改密码不是"通知全网换账号"，它只是一组本机与数据面动作，身份本身纹丝不动：

- **改密是单机动作**：用旧密码解锁后设置新密码，只重新加密本机的身份文件；助记词不变、RootID 不变、你在各组织的身份与名册关系都不变；
- **全账号单一密码**：为防多台设备密码分叉（A 设备改成 X、B 设备改成 Y），新密码须通过账号级校验——用它能否解开账号内的一份公开校验凭证来判定——通过才允许本机重封。校验只发生在本机，**密码永不上网**；
- **其他设备不受影响地登录**：改密不踢任何设备，其他设备仍用各自旧密码照常解锁本机；要踢设备走[设备撤销](#设备信任事后发现--止损而非事前堵死)；
- **数据面换锁（epoch 轮换）**：改密会向你的设备群广播一个换锁标记，此后产生的数据用新锁。设备须用新口令完成一次确认才能领到新锁钥匙——**输密码解锁即自动完成，用户无感**；不知道新口令的设备（遗忘在抽屉里的、丢失未撤销的）自动"断粮"，拿不到新数据。曾正常使用的设备有 7 天宽限期，从未验证过的设备（含刚配对的）不适用宽限、立即暂扣；
- **其他设备看到的流程**：上线后收到"密码已在他端变更"的引导，输入一次新密码即同时完成三件事——单密码校验、本机重封、领取新锁钥匙。口令全程不出设备，网络上只有密文与校验凭证。

## 设备信任：事后发现 + 止损，而非事前堵死

- 设备管理页列出全部已配对设备；**新设备配对 / 恢复时通知已有设备**（best-effort 提醒，不是安全保证——恶意恢复方可以不通知）；
- 发现异常设备可**撤销**：撤销即断连（其他设备拒绝它的连接与同步请求），并触发密钥轮换，使它**解不开此后产生的新数据**；
- 诚实边界：撤销令在对方离线时延迟到达；且**它此前已下载到本地的旧数据无法被远程抹除**——断连防的是未来，不是过去，设备物理安全仍由用户负责；
- 配对即全量信任（与 [personal-data](personal-data.md) 一致）：经配对通道加入的设备持有完整身份，最坏后果等同助记词泄露，所以延迟恢复的"通知 + 延迟 + 否决"是必需品，不可省略。

**设备层数据隔离（OS 账号）**：桌面端数据目录放在 OS 用户目录下、借操作系统文件权限做本机隔离——一个 OS 账号即一个逻辑设备（各自的 Spark 实例与数据目录）；多人共用一台电脑（如家庭小主机）时，每个成员用自己的 OS 账号登录即天然隔离，OS 文件权限就是边界。**不硬绑**"一台设备一个账号"：同一 OS 账号下要隔离就另开根身份（与 personal-data 的立场一致），账号数量是你的自由。这是本机静态层的纵深防御（防同机其他用户 / 进程），不是加密的替代品；移动端 OS 沙箱天然已提供应用级隔离。

## 边界（这一层不做什么）

- 不做中心化账号体系：不绑定手机号 / 邮箱 / 实名即可运行（组织内是否要求实名是组织规则，不是内核要求）；
- 不做跨**身份域联邦**：不用这套身份去登录系统外服务，也不在相互独立的网络之间互认身份；RootID 更不是"万能通行证"——它不自动授予任何组织的成员资格，进入一个组织仍须经该组织确认（见 [membership](../community/membership.md)），且你在各组织的身份默认互不可关联；
- 不提供任何绕过密码 / 助记词的即时找回或万能恢复；
- 根身份及其标识对上层（插件、组织）完全屏蔽。
