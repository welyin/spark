# 网络：让成员感觉不到网络的存在

> 状态：定稿 ｜ 分册：第一层 · 底座
>
> 上游实现：`wiki/architecture/p2p/*`、`wiki/product/relay-strategy.md`、`wiki/product/mobile-leaf-mode.md`、`docs/protocol/p2p/*`

## 一句话

两台设备之间**优先直连**；而真实网络里大量设备互相拨不通（运营商 NAT、入站拦截是常态而非例外），系统用"**打洞 → 中继 → 离线暂存**"三级兜底自动完成通信，用户无感——设计验收标准只有一句：**成员感觉不到网络的存在。**

## 真实世界的三道难题

没有中心服务器，就要靠节点互助解决三件事：

1. **拨不通**：蜂窝 CGNAT、家用光猫 / SPI 防火墙拦入站 TCP（常常 ICMP 通、TCP 握手却建不起来），两端可能都无法被对方直接拨入；
2. **地址会变**：WiFi / 蜂窝切换、家宽公网 IP 重分配、IPv6 前缀变化后，旧地址失效；
3. **对方不在线**：消息发出时对端根本没上线，得有地方让密文先等着。

## 一条连接纪律：能直连绝不绕路

```
直连  >  自己设备 / 本组织中继  >  全网共享池中继
```

- **直连手段**：局域网自动发现、UPnP/NAT-PMP 端口映射、AutoNAT 自测可达性、打洞（DCUtR）在建立中继后尝试升级回直连；
- **懒连接哲学**：只在发送时、登录时、网络恢复时拨一次，失败就沉默换备，不做周期性骚扰；
- **重寻址**：切网 / 变 IP 后经全局 DHT 竞速找回对端最新地址。覆盖网邻居层只负责"谁是活节点、最新地址是什么"，与"谁有权进组织"严格分离；地址宣告报文不含 rootId，**不向陌生节点泄露组织归属**；组织整体失联时还有受限、不洪泛、非成员无法枚举的组织恢复面。

## 中继：公网节点的自然属性，不是服务商

中继（relay）解决"双方都在线、却互相拨不通"：两端各自**主动出站**连到同一台公网中继（出站方向运营商从不拦），由它转发。

- **中继不是一种专门服务，而是公网 Spark 节点的自然属性**：节点经 AutoNAT 判定自己公网可达，就自动开启中继、在 DHT 共享池发布；任何人上线即可查到全网可用中继，零配置、无组织关系要求；
- **想让网络更稳，就在一台公网机器上跑 Spark**：内置"托管节点向导"，自检当前网络（UPnP 是否成功 / IPv6 入站是否被拦 / 光猫是否桥接），并给出针对性引导；
- **选择纪律**：优先用自己设备 / 本组织的中继（信任天然存在），陌生人的全网共享池只作兜底。

**必须对用户讲明的信任边界：**

- 中继只搬端到端密文，**读不到内容**，作恶最多丢包、丢包即换；
- 但中继**看得到"谁和谁、何时、传了多少"的流量元数据**——比能读内容的中心服务器好得多，但不是零暴露；
- 中继**有配额**（限时长 / 限量）防滥用，**可替换、非单点**，不存在"唯一桥梁"。**切换中继零成本**：中继无状态——无需注册、不保存你的数据、切换不需要任何人批准，这是"这张网无人能够收购"在网络层的具体含义；
- 官方**不运营、不预置**任何中继服务器；一个组织里只要有任何一人有公网可达的机器，全组织的蜂窝连通即通。

## 对方不在线：网关邮箱与离线暂存

一句话分清职责：**中继管"在线但打不通"，网关管"不在线"。**

- 组织里没有专门的"服务器节点"、只有账号：**网关是一种角色**，由组织内少量活跃成员自荐轮流承担（其任一在线设备履职），缺省全体成员都是候选；**网关不可被指定**——没有"管理员指派网关"的入口，全员候选 + 活跃轮流是唯一策略：通信面与数据面一样，不允许长出权力中心（承接 [membership](../community/membership.md) §四"结构角色不是权力角色"）；
- 对方离线时，发给它的信封以**密文**暂存在网关，等它上线后转发，转发成功回"已接收 / 已转发"；双方同时在线则直连、不经网关；网关也离线时由发送方本地暂存、上线重发，并按消息唯一标识去重；
- 网关**不是数据权威、不存组织明文**，作恶只能丢信、不能读信；
- **跨组织异步投递**：组织地址自认证 + 公共 DHT 解析 + 网关邮箱，让 A 组织成员能向此刻离线的 B 组织成员投出密文信封。

## 手机是叶子：只消费、不服务

手机为"参与构建网络"持续付出电量 / CPU，实际贡献却接近零，因此叶子化：

- **砍掉一切"为网络 / 他人服务"的角色**（不做 DHT 托管、不广播、不为他人转发），保留全部"我要什么"的消费能力；
- **自设备空间多连接**（全部自有设备在线即连）；**组织空间单连接**——任一在线成员 PC 都能服务它，只有离线暂存、地址发布这两件脏活才优先找网关活跃集；
- 手机保留监听与中继客户端（让自有 PC 局域网反拨、蜂窝可达）；砍掉对外宣告后，"手机存在性"不再进入 DHT，**隐私面反而收窄**；
- 自有 PC 全离线时，个人域写入本地排队，PC 回来后自动收敛、零丢失。

## 离线通知的诚实边界

无中心服务器，App 被系统杀掉后，**没有合规手段保证手机即时收到推送**。主路径是前台保活 + 系统通知 + 自设备同步；而"把新消息提醒转发到钉钉 / 飞书 / Telegram / 邮件"这类借第三方厂商通道的能力，是**用户自选安装的插件**（见 [../plugins/catalog.md](../plugins/catalog.md)），不是内核：提醒会经过第三方服务器、默认只发"有来自 X 的新消息"这类元信息、正文默认不外发，装不装、信不信由用户决定。

## 边界（这一层不做什么）

- **不保证 100% 可达**：双方都困在严格 NAT 后、全网又无可用公网中继时，会退化为"局域网可用 + 经他人中继中转"，不会为了兜底偷偷引入官方服务商；
- 覆盖网给出的地址永远只是"拨号提示"，不直接写入组织成员表，成员资格仍走组织层校验；
- 中继、网关都不碰明文，所有公共组件遵循"不可信、可替换、非单点"。
