# 基础插件清单（catalog）

> 状态：定稿（随里程碑滚动更新）
>
> 本篇只登记**两个里程碑分别需要哪些基础插件、各自做什么、当前什么状态**，不记录任何插件的具体实现（运行时、协议、SDK 见 `wiki/architecture/plugins`、`docs/protocol/plugins`）。
>
> **状态三档**：计划 / 开发中 / 已开发版本。
>
> **不在本清单内**：统一 DM 底座与通讯录数据、链式存证与独立核验、文件同步（Git 仓库分发即复用它，无独立 Git 协议层）、分发协议与验签、身份与签名是内核 / 协议能力，不按插件登记；默认内置应用（聊天、通讯录、组织管理、文件、应用市场）都是可替换的独立插件，其演进属各插件自身事务，不进 Spark 里程碑。

---

## 里程碑一：Spark 自举

> 目标（阶段⑥）：Spark 自身的开发、发布、分发、反馈闭环全部在 Spark 上完成。源码仓库经内核文件同步分发（只读镜像，无独立 Git 协议层）、签名发布与 P2P 分发走内核与市场能力，其余协作由下列基础插件承载。
>
> 基础插件按**可组合基础件**设计——小粒度、单职责、可独立使用，后来者可经插件间契约（见 [plugin-types](plugin-types.md)）自由组合；构建打包本身在系统外工具链（构建机 / CI），Spark 承接构建产物。
>
> 各插件的产品设计草案见 `wiki/product/bootstrap-plugins/`（设计细节不进 docs）。

| 插件 | 功能说明 | 状态 |
|---|---|---|
| 项目（自举第一插件，即议题） | "项目"类型的事务：一个项目就是一个议题（事务容器，可公开发布进公共目录）——讨论与子事务（bug / 建议走父子引用）、文档、成员与发布；以**库依赖**把代码仓库、看板、发布管理等基础件组合成统一工作区（构建期复用，见 [plugin-types](plugin-types.md)）；"议题驱动开发"的主战场、公共议题平台的参考实现 | 计划 |
| 代码仓库应用 | 仓库浏览、提交历史、分支与 diff 视图；项目仓库经内核文件同步分发为**只读镜像**（Git 对象本身内容寻址），本地 git clone 自便；改动走 PR 流程（子事务 + bundle / patch 附件），维护者本地合并后同步分发。桌面随应用安装本地 git CLI，移动端以 isomorphic-git 只读浏览 | 计划 |
| 论坛 / 讨论板 | 开发讨论、方案沉淀的主题讨论区 | 计划（可由 spark-example 演化） |
| 公告通知 | 版本公告、团队通知，经应用会话推送消息卡片 | 计划 |
| 问题反馈 | 对运行版本提交反馈、回流为开发事务 | 计划 |
| 任务看板 | 开发任务与缺陷的看板跟踪 | 计划 |
| 发布管理 | 构建产物登记、签名发布、渠道与更新跟踪 | 计划 |
| 积分规则包（自举版） | 开发贡献的发行策略（PR 合并 → X 分、需求被采纳 → Y 分等规则化发行）+ 兑付目录；自举社区是积分的第一个真实用户 | 计划 |

## 里程碑二：小区自治

> 目标（阶段⑦）：真实业委会用插件走完"筹建 → 签名征集 → 投票 → 结果提交街道办"，存证导出包 + 独立核验工具使结果被接受。业务插件抽象自业委会法规全生命周期（详见 `wiki/product/hoa-plugins.md`）。
>
> **MVP 铁三角 = 签名表决 + 公共账本 + 信息公示**，流程向导承担获客入口。

| 插件 | 功能说明 | 状态 |
|---|---|---|
| 流程向导 | 通用多步流程引擎：声明式流程包 + 法定时限跟踪 + 进度存证；"业委会筹备"是首个流程包 | 计划（MVP 入口） |
| 签名表决 | 联名征集 + 正式表决合一，专有面积/人数双维度计权，全过程链式存证 | 计划（MVP 铁三角） |
| 选举 | 候选人管理、委员会组成约束校验、届次与任期登记 | 计划 |
| 公共账本 | 公共收益记账、管理成本上限校验、多签支出，提供只读监督接口 | 计划（MVP 铁三角） |
| 信息公示 | 法定公示事项发布、公示期计时、发布即存证防抵赖 | 计划（MVP 铁三角） |
| 会议管理 | 会议召集规则校验、记录归档、决议联动公告 | 计划 |
| 档案与用印 | 工作档案库、用印审批留痕、换届逐项移交 | 计划 |
| 监督审计 | 聚合各业务插件只读接口的监督驾驶舱（无数据特权） | 计划 |
| 知识库 | 法规 / 模板 / 流程包的结构化检索分发与合规日历 | 计划 |
| 身份认证 | 成员 / 户主资格核验并签发业主凭证（验证插件，"插件是方法、验证人才是信任"） | 计划（已有演示级开发版本 spark-verify-hoa，见下表） |
| 交付佐证 | 兑付交付的佐证采集（照片 / 签收 / 多人见证）与"什么佐证触发什么状态迁移"的规则声明，挂在内核兑付单状态机上 | 计划（模板层参考实现，可替换） |
| 积分规则包（社区版样本） | 单组织积分闭环的发行策略与兑付目录（时间银行 / 定额计件等模板层样本，组织显式选用或改写，无隐式默认） | 计划 |
| 经营账 | 组织对外经营的法币收支留痕、与积分账物理分账（两个数据域、两个决策程序）、分配决议走事务；纯信息留痕工具，内核不提供任何法币通道（见 [economy/fiat-compliance](../economy/fiat-compliance.md)） | 计划（模板层候选） |

## 已有可复用插件

| 插件 | 功能说明 | 状态 |
|---|---|---|
| spark-example（组织微博 / 示例插件） | 基础协作与插件开发参考样例，已上架应用市场 | 已开发版本（0.1.0 预发布） |
| spark-moments（朋友圈） | 个人空间动态、点赞评论、消息卡片视图 | 已开发版本（0.1.0） |
| ai-chat（AI 助手） | 个人空间 AI 对话助手（当前桌面端）；AI Bot 与其他业务插件地位相同，不享有内核特权 | 已开发版本 |
| spark-affairs（公共议题客户端） | 公共事务（affair）参考客户端：事务墙、议题详情（日志时间线 / 规则 / 阶梯状态）、发起议题、提交贡献与投票；事务数据属于议题本身，本插件仅为参考实现 | 已开发版本（0.1.0，个人空间） |
| spark-verify-hoa（业主资格验证示例） | 验证插件参考示例（业主场景，组织空间）：申请人材料提交引导 + 验证人审核签发资格凭证，演示"插件是方法、验证人才是信任"的分工；演示级实现，签发 / 注销以插件域身份签名，凭证不与内核凭证体系互操作（见插件 README 诚实口径） | 已开发版本（0.1.0） |
| spark-threshold-vouch（担保链门槛示例） | 门槛插件参考示例：被担保人发起请求，N 名参与者担保收齐后组装"是否满足门槛"的签名证明，内核 / 事务客户端只验证产物、不执行担保流程；演示级实现（担保与组装签名为插件域身份） | 已开发版本（0.1.0） |
| spark-minichat（最小聊天） | 第三方最小聊天插件示例（communication §六验收样例）：仅 sdk.messages 四调用，证明换前端后同一消息数据原样在 | 已开发版本（0.1.0） |
| 聊天应用（默认内置） | 会话列表与消息界面（未来含群聊）；可整体替换的独立插件，不享有内核特权 | 默认内置插件（.spkg 分发，plugins/spark-chat，0.1.0） |
| 通讯录应用（默认内置） | 人脉展示与管理（好友 / 标签 / 拉黑 / 组织成员视图）；通讯录数据内核级，应用可整体替换 | 默认内置插件（.spkg 分发，plugins/spark-contacts，0.1.0） |
| 组织管理应用（默认内置） | 创建组织、名册管理、策略配置、副本健康度展示；数据与操作在内核，界面可替换 | 内置（插件化重构中） |
| 文件应用（默认内置） | 个人空间与组织域统一的文件 / 照片管理（网盘体验）；数据在内核、各走各的域边界（个人域 / 组织域），界面可替换 | 内置（插件化重构中） |
| 应用市场（默认内置） | 应用的发现、安装与更新界面；签名验签、信任级判定、仓库锚定是内核 / 协议能力，多市场镜像天然支持 | 内置（插件化重构中） |
