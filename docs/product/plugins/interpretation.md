# 解释权模型：规则下放，但结果可复现

> 状态：定稿 ｜ 分册：第五层 · 插件
>
> 上游：`docs/protocol/community/policy.md`（声明式策略求值）、`wiki/architecture/community-affairs.md`（插件分工）。

## 定义权与解释权

- **定义权（内核保留最小集）**：这套体系承认哪些"无字的机制"——根 / 域 / 设备三层身份、无归属事务容器、凭证、数据集合、积分状态机、链式存证。它们数量极少、不含任何业务立场，任何组织都绕不开也改不了。
- **解释权（下放给组织与插件）**：在一个**具体组织**里，"这件事按什么规则成立"——这算哪类事务、谁有资格参与、贡献值多少、什么条件算通过、谁能看到哪条数据。内核不表态，由组织选用的开源插件 / 规则来定义。

传统软件把这两者都攥在厂商手里；Spark 只保留前者，把后者整体下放。

## 解释的两种产物（关键区分）

插件对机制的"解释"必须落成下面两种**可被内核独立对待**的形态之一，而不是一段在关键时刻自己运行、自己说了算的代码：

### A. 声明式规则文档 —— 内核确定性求值

插件作者把规则写成**声明式文档**（"什么集合向上级开放、名册开放到哪档、哪些字段逐字段授权、表决阈值是多少、积分刻度几位"），组织启用后，**每次判定都由内核的求值器在执行点完成**，插件代码不参与：

- **结果全网可复算**：求值是纯函数，不碰网络 / 存储 / 本地时钟，输入相同结果必相同；
- **fail-closed（缺省拒绝）**：没有明文声明的，一律不开放、不暴露；
- **静态分析兜底**：保存规则时自动检查冲突与不可达项（阻断），并对"暴露面比上一版扩大"给出必须显式确认的告警——防的是借升级悄悄放宽规则；
- 规则文档按其哈希自认证，被篡改一个字节即失配、拒绝执行；
- 内核只内置一套**最小规则集**起步，并为将来换更强的规则语言预留出口；遇到当前求值器不认识的规则，直接拒绝而不是猜着执行。

> 典型场景：名册开放三档、字段级授权、向上开放矩阵、成员城门验证（成员资格凭证验签 + 名册回查）。可见性在**写时**由开放声明决定，读时只剩这一道城门。

### B. 凭证 / 产物 —— 内核只验证产物

另一类判断无法写成确定性规则（"这人是不是真业主""是否满足某个现实门槛"），由插件通过**人机流程**产出一张**凭证或签名证明**，内核**只验证产物的形式与签名是否成立，不重跑、也无法重跑背后的现实判断**：

- 凭证只携带**结论字段**（如户号），禁止携带姓名、证件号等身份标识（最小披露）；
- 凭证由域身份签名、插件无法自报；插件本身**没有签发接口**，签发走验证人的人机流程；
- 因此"**插件是方法，验证人才是信任源**"：内核证明"这张凭证确实由该验证人签发且未被篡改"，但"这个验证人可不可信"是组织的治理决定，可被集体撤销（既往不咎，已发凭证逐条注销）。

> 典型场景：业主 / 居住资格凭证、担保链、成本类门槛。

## 为什么"执行点"不能跑插件自有代码

如果判定时刻允许插件运行自己的代码，同一条规则就可能在不同成员设备、不同时刻给出不同结果——集体决策的计数、存证链的一致性、跨组织清算的套算都会失去确定性地基；也会留下"源码看起来合规、运行时偷偷作弊"的口子。所以：**规则可以由任何人写（开源），但对规则的执行必须收归内核、且确定可复现。** 下放的是"定规则"的权力，不是"私自执行规则"的权力。

## 三级公开（与经济层同一口径）

1. **规则文本公开**：组织启用了哪套规则、参数是什么，成员加入前可见；
2. **规则实现公开**：承担判定的插件源码可审——**闭源插件不得执行经济 / 资格 / 治理规则**；经手个人敏感材料的验证类插件**强制源码公开可审计**；
3. **执行结果可核验**：每次求值 / 凭证的输入与结果留痕，成员可用独立工具复算。

## 规则即立法、版本化、可替换

- 组织启用某插件 = 选择并采纳一套规则，属组织立法行为，其采纳 / 更换本身要走组织自己的决策程序；
- **规则代际化**：规则 / 数据集合带版本，代际内冻结不可改，升级 = 启用新一代，旧规则不溯及既往、存量不被悄悄重算；
- **数据属于组织（容器 / 议题），不属于插件**：业务数据存在内核与同步层，换掉任何一个插件 / 客户端，数据原样还在。解释权因此**可收回、可迁移**——这保证了"定义权去中心化"不会反过来变成"被某个插件 / 作者绑架"。

## 边界（这一篇不做什么）

- 内核不内置任何业务规则模板作为默认值（模板层样本必须显式选用，无隐式默认）；
- 内核不替组织判断规则"公不公平"，只保证它声明一致、求值确定、变更留痕；
- 内核不验证凭证背后的现实真伪，只验证凭证本身的签名与形式。
