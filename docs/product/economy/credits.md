# 积分：发行、生命周期与组织内分配

> 状态：定稿 ｜ 分册：第四层 · 经济
>
> 母稿：《共同体经济系统设计.md》v0.10 §2、§3。

## 一句话

积分是**组织对持券人的资源兑付承诺**（组织的负债，不是资产魔法）：它记名、带唯一序列号、只在发行组织兑付、**兑付即销毁**；怎么挣、挣多少由组织公开规则与集体评定决定，内核只保证它发得合法、流得可追、销得可见。

## 积分的性质

- 只在**发行组织**兑付，兑付即销毁；
- **记名**：与成员身份绑定，每一单位带唯一序列号（类比纸币冠字号），全生命周期可追；
- **定点刻度**：数量是离散定点值，显示层可以是小数，最小刻度（小数位数）由组织在规则包里声明；存储与运算一律是该刻度下的整数，**禁用浮点**（分布式下两个独立节点必须落同一个离散值，无限小数无法判等）；
- 不保值、不承诺与任何外部货币等价、不产生孳息。

## 贡献怎么评定：方法自定，授权集体，过程公开

**评定方法属于政策层，内核不做规定**：时间锚、定额计件、集体评议或混合制皆可。内核只强制两件事：

1. **发行必须依据经事务决议授权的发行策略**（经济宪章层不变量）：策略的立改废走公示延迟决议；**策略内的发行由内核按规则确定性执行**（触发事件须来自存证链 / 事务日志的可验证记录，如 PR 合并、贡献被采纳）；**策略外的裁量发行**（一次性奖励等规则外情形）逐次走决议。协议不存在私钥直接发行接口——这是不变量，不是评分方法；
2. **评定过程对成员可核验**：依据、结果、变更全程留痕；申诉 / 仲裁程序由组织规则与插件提供，内核不内置。

若组织选择集体评议路线（**推荐实践，非默认**），模板库可收录这些经验：事实与评价分离（只记录可核验事实、集体只对"事实→分值"表决，不对人品态度打分）；评审组轮换 + 回避 + 申诉（治理者不评自己）；限域公开（评分仅对本组织成员，不跨域、不进公共履历）；小共同体兜底（评议摩擦在几十人、可退出的叶组织内才可承受）。

## 序列号、状态机与恒等式

```
issued（按经授权的发行策略 / 裁量决议发行）
  → held（成员记名持有）
    → locked（跨组织消费受理中，短暂锁定）
      → redeemed / burned（兑付资源、销毁，序列号进销毁日志，永久退出）
```

- 全部状态迁移走 append-only 流水 + 链式存证；
- **恒等式（任何成员随时可核验）：发行总量 = 已销毁 + 在外流通**；
- **销毁必须被见证**：兑付时序列号写入销毁日志，防经办人收券不销、重复兑付。

## 发行治理与两类积分

- 发行策略（规则、额度、依据）的立改废属组织级效力，必须经公示延迟决议；策略内发行由内核按规则自动执行、逐笔留痕；发行 = 负债增长，账本必须同时呈现"**在外积分总量 vs 组织可兑付资源**"，任何成员可见，防超发挤兑；不得按出资、职位、关系发行；
- **两类积分分立、不得混账**：**贡献积分**（劳动挣得、兑付即焚）与**权益凭证**（预先获得的资源使用权、预付性质、不设找赎套现、单独记账）。

## 规则必须三级公开、版本化

1. **规则文本公开**：发行依据、评定方法、兑付目录、储备规则、变更程序，成员加入前可见；
2. **规则实现公开**：承担经济计算的插件必须开源可审计，**闭源插件不得执行经济规则**；
3. **执行结果可核验**：发行 / 销毁流水、恒等式、往来头寸对成员与签约对方开放，可用离线工具复算。

规则可演化但受控：变更必须走组织**自己声明的修改程序**（内核只校验"这次变更是否符合其声明程序"）；设公示期 / 时间锁，禁止"今晚改规则、明天收割存量"；**规则版本化**，每批积分记录当时适用版本，存量不溯及既往；规则历史永久留痕。

## 特殊生命周期

- **成员退社——权益与历史解耦**：存量积分按**加入时已公开的规则**处置（限期兑付 / 正常兑完 / 作废，政策层自定、禁止临场剥夺）；**贡献历史是事实层，与成员资格永久解耦**——退出不删不改、永久可查（人可以走，事实不走）；
- **主体消亡（死亡 / 失能）：不存在继承**。积分具人身性、不可转让，继承本质是死后转让，一并禁止；存量按公开规则处置（默认回归公共储备），贡献历史永久存档但不产生权益承继；
- **积分时效**：内核提供到期原语，是否设效期、多长属政策层；不设则组织承担永久负债；
- **纠错（红冲）走正常流程**：历史不可删改，红冲不是后门，而是一笔**需要同等集体授权的普通追加事务**——引用并抵消指定历史批次、恒等式联动重算；已跨组织销毁的部分沿原路径反向追加，确实追不回的计入组织损失，**不得摊派给其他成员**；
- **兑付紧张（微观挤兑）**：可兑资源低于在外积分时，按事先公开规则触发限额 / 排队 / 暂停新增发行；排队顺序确定（按申请序号），任何身份不得插队，健康度同步标红。

## 兑付端最小机制：只管"锁—确认—销"，不做电商

积分闭环最后一段是兑付。Spark **不做电商 / ERP / 库存管理**——供给什么、怎么生产、定价、目录呈现都是组织经营与插件的事；内核只立一个最小对象**兑付单**及其状态机：

```
proposed（成员发起，held→locked 锁定）
  → accepted（供给方确认可交付 / 预约成立）
    → delivered（交付完成并确认）→ burned（销毁，序列号入销毁日志）
  异常：rejected（无货 / 无档期 → 解锁回 held）｜timeout（无响应 → 自动解锁）
        disputed（交付争议 → 维持锁定、挂起，等组织规则认可的裁决凭证，内核不裁决）
```

三类供给只在"**交付确认时机**"上不同，内核不管经营过程：实物在领取 / 签收时确认；服务 / 劳动在完成时点确认（预约即锁、完成才销、取消即解）；资源使用权在使用时段结束时确认。

**最小供给声明**：组织维持一份可兑付供给的结构化摘要（可兑项目、计价、可供能力），它是"在外积分 vs 可兑资源"与健康度的**分母**，也是其他组织判断是否受理的依据。**内核不核实声明真伪**（真实性靠集体决策与声誉），只保证它结构化、版本化、变更留痕，并确定性算出比值；严重不符属治理 / 欺诈问题，走申诉事务。

**交付佐证由插件定义**：内核的交付确认流程即上面的兑付单状态机；佐证的**形式**（照片 / 签收 / 多人见证等）与"什么佐证触发什么状态迁移"的规则由插件提供——模板层收录参考实现（见 [catalog](../plugins/catalog.md)），它是可替换插件，不是内核义务。

## 组织内的分配、储备与法币收入

- **不可分割储备**：内核提供"进得去、没有按份私分出口"的账户结构；**是否设立、规模多大属政策层**；一旦选用，组织解散时余额不得私分、只能转入同类共同体——这是阻断"盈余→个人本金→G—W—G′"的核心装置；
- **当期分配与长期荣誉分立**：积分管当期消费（兑付即焚）；长期荣誉（贡献档案、称号）由插件对链上贡献记录做视图呈现——事实在链上永久可验（这是内核保证的），档案长什么样是插件的事。**成员出资不设内核对象**：要不要出资、怎么记账、如何偿还，是组织自己的经营问题——系统外（借条 / 银行）或插件自行管理皆可，Spark 不干涉、不提供任何"资本账户"结构；
- **治理岗位的经济约束**：治理 / 协调 / 主持也是劳动、照常有积分，但标准由集体定、岗位可轮换、可被决议撤换；治理者报酬对成员平均报酬的**倍数上限由章程锁定**（防自定高薪形成事实阶层）；治理者不得评定自己的贡献；
- **法币经营收入**：法币在系统外的银行账户里，**不归 Spark 内核管理**——组织可用插件自行记录经营账与分配决议（信息留痕、可审计），实际收支与分配走现实财务程序；与积分账**物理分账、两个决策程序**；
- **公共扣除与发行分流**：内核提供发行分流原语——一笔经授权的发行按公开比例自动拆入个人账户与公共储备池（用于再生产、互助保险、教育济贫）；扣除比例与用途属政策层、公开并经事务调整；公共储备池纳入不可分割储备，不得按份额私分。

## 边界（这一篇不做什么）

- 不内置任何"公平分配公式"或默认评分方法，不判断贡献值多少；
- 不做电商、库存、预约排班、定价与经营分析；
- 不做积分转让 / 继承 / 对私兑现，不做计息与理财；
- 不做争议裁决，争议只挂起、等组织自己的裁决凭证。
