# 跨组织经济：双边受理网络

> 状态：定稿 ｜ 分册：第四层 · 经济
>
> 母稿：《共同体经济系统设计.md》v0.10 §4。

## 一句话

组织之间不"兑换货币"，而是**相互受理**：双边协议约定"任一成员可凭其本组织积分，在对方组织按约定折算消费"。于是**个人永远只持有本组织一种积分**——不用找交易对手、不持有外币、不承担外币风险；组织之间用往来账记账、定期以真实资源平仓。

## 本质是相互受理，不是货币兑换（四方模式）

| 银行卡世界 | Spark |
| --- | --- |
| 持卡人（消费者） | 成员（只持本组织积分） |
| 发卡银行 | 成员所属组织（发行方） |
| 特约商户（受理外卡） | 受理组织（交付资源方） |
| 卡组织（银联 / Visa） | Spark（套算、传凭证、记净额、见证，**不持仓**） |

一笔跨组织消费（甲是 A 组织成员，持 A 积分在 D 组织消费）：

1. 甲签发消费单，D 按双边协议折算并交付资源；
2. **消费者侧当场核销**：甲的 A 积分当场扣减、销毁回发行方 A；
3. **受理侧取得债权**：D 记一笔"应收 A"；
4. **发行方确认负债**：核销凭证送达 A，A 记一笔"应付 D"；
5. **Spark 的职责**：传递并见证凭证、按协议套算、维护往来余额、存证——不垫券、不持仓、不做交易对手。

个人层"消费即焚"的纯粹性由此保住，组织层只留下一笔双边往来账。

## 两层：汇率发现 与 清算交割

| 层 | 职能 | 中间组织是否参与 |
| --- | --- | --- |
| 汇率发现层 | 在双边协议图上套算任意两点理论汇率、枚举路径、展示全路径汇率构成 | **不参与**——纯本地确定性计算，任何节点结果一致、不产生费用 |
| 清算交割层 | 真实资源交付与债权债务落账，只能沿"有受理协议且授信余额非零"的边走 | 必须真实发生 |

**报价 ≠ 可成交价**：理论汇率永远可算；但没有真实受理边时，必须诚实返回"有理论汇率、无清算路径"并拒绝成交，**不得诱导受理方收下变不了现的积分**。选径规则确定性（同一张图同一时刻任何节点选出同一条路径），全路径汇率构成向消费者明示、可拒绝。

## 往来账、净额与平仓

- 双向消费自然对冲（A 成员在 D 消费、D 成员也在 A 消费），只有**净额头寸**需要处理；
- 净额**定期以真实资源 / 服务平仓**：不用法币、不用新积分展期，**严禁借新还旧**（那是庞氏入口）；
- 平仓周期写入双边协议，缩短风险暴露窗口。

## 净应收上限：授信边界

每条双边协议必须约定**双向净应收上限**——"我最多愿意被你欠多少"；达顶即**暂停受理**对方成员，风险到边即止，平台不替任何组织做信任判断。额度各组织自定、可随时收紧，占用情况对双方成员可审计。

> 排期注记：本篇所述跨组织双边受理与清算机制，在 roadmap 上整体位于里程碑二（小区自治）之后——前两个里程碑只做单组织闭环；文中 "v1 / v2" 指**机制形态分层**（直接双边 / 代理受理链），不是产品里程碑。

## v1 直接双边，v2 代理受理链

- **v1**：没有直接受理协议即拒绝。社区 / 街道尺度两两签约密度足够覆盖绝大多数消费，不为长尾提前复杂化；
- **v2**：当 D 不直接认 A、但协议图存在路径 A→B→C→D 时可经链接单。铁律是"**信息沿链传递，信用不沿链传递**"，四层职责严格分开：

| 层次 | 谁参与 |
| --- | --- |
| 汇率层 | 纯本地套算，B / C 不知情、不在线、不参与 |
| 资源交付层 | **只有消费者与受理组织双方**：只有甲付券、只有 D 交付真实资源，B / C 不交付任何资源 |
| 体验层 | **只有双方**：甲只看到"按套算汇率消费成功"，路径自动执行、无人审批 |
| 账目层 | 自动生成**成对、净额为零**的逐跳往来账（D 应收 C、C 应收 B、B 应收 A），每个中间方应收 = 应付、净头寸恒为 0；最终只有 A 净应付、D 净应收 |

- **每一跳仍是独立的双边授信**：D 只对 C 有应收，永不对隔层的 A 产生信任；
- 中间方是**零净敞口的自动管道**、不是交易参与者；原子交割（沿链锁定、要么全成要么全回滚）把在途风险压进原子区间；
- **不收路由费**：净额为零、风险趋零、自动执行的中转收费等同于抽租；协议在**结构上不设费用字段**，想按笔抽成都没有落点，无需事后审计；
- **骨干服务在协议外**：运营公网中继 / 骨干网关是协议外的普通服务，谁都能提供、按独立双边服务合同自由收费（年费 / 带宽批发，允许合理收益，和采购云服务无异），Spark 不审价；唯一界限是服务费必须独立于单笔清算、**不得按笔绑定**（协议无费用字段，物理上做不到）；
- 中转的非货币激励：**权义对等**（承担中转义务才有权用他人中转，关闭则对等关闭，同 BT 做种）、网络互惠、中转量计入组织贡献记录（链上事实，档案视图归插件；不提现、只影响声誉与授信地位）。

## 路径预算：在效率与可达之间取平衡

不设单一跳数常数，**横跳 / 层跳分开计数**：

- **横跳**（叶组织之间的对等边）：邻域规模随跳数指数膨胀（每节点约 20 个邻接时，3 跳约 8 千、4 跳 16 万、5 跳 320 万），物理墙在 3~4 之间，故**默认 2、硬顶 3**；
- **层跳**（经递归共同体枢纽的聚合边）：沿共同体树上行到最近共同祖先再下行，成本只等于树深——亿级节点、扇出 20~50 时树深仅 5~6 层，**上限 6~8**；
- 真正受限的是**经济成本而非跳数**，四项预算并行：汇率滑点上限、在途锁定时长（超时全链回滚）、每边剩余额度（流动性连乘——每边可用率 0.9 时 3 跳成功率约 73%、6 跳约 53%，长路径主要死于额度凑不齐）、跳数粗筛；
- 内核只设**安全天花板**（横跳 ≤3、总中转 ≤8，兼作套利环防护），默认半径政策化，模板提供"社区型（横 2 / 层 4）""区域型（横 3 / 层 6）"样本；
- **回退阶梯**：短预算失败 → 逐级放宽到天花板 → 走层次枢纽 → 仍失败则诚实拒绝并建议双方直接签约。消费需求驱动签约，网络自我稠密化，长期平均跳数递减；原子交割下多跳不放大坏账（失败即整链回滚、无损失）。

## 不产生行情

系统**不做订单簿、不撮合、不展示成交均价、不生成浮动市场价**。路径汇率只是双边**合同条款**的确定性套算（协议相对静态，图改了结果才变）；汇率的"立法权"完全在签约组织、且签约须经双方各自按自声明策略的决议（公示 + 延迟 + 留痕）；Spark 只是计算器。

## 网络准入：强制披露，不做内容审查

组织内部规则再异质也是成员私事；但一旦要求本组织积分被他人受理，规则就产生了外部性。因此跨组织网络只设一道门槛——**强制披露**（完成规则三级公开、持续提供健康度），不设内容审查：

- 签不签约、授信多少、汇率几何，全部由交易对手自主判断，Spark 不评价规则优劣、不为任何组织背书；
- 可疑组织（无限增发、管理员单方发券、拒绝披露）**不会被封禁，但不会有人愿意与其签约**——其积分出不了本组织。**自由的代价是自担孤立，而非被平台处罚。**

## 实报实销：不允许离线 / 赊账式消费

- 跨组织消费必须**当场在线**完成发行方确认与核销，发行方不可达即交易直接失败——宁可刷不了卡，也不产生"先交付、后追账"的脱机信用；
- 在线两阶段：发行方在线核验并锁定 → 受理方见有效锁定凭证后交付 → 最终销毁落往来账；任一步失败 / 超时即整体回滚；v2 多跳整条链在线原子完成；
- **可用性是发行组织自己的责任**：成员要能在外消费，其组织必须保证网关 / 中继高可用（如同发卡行必须保证支付系统在线）；自己的网关不在线，自己的成员就消费不了，责任不转嫁受理方；离线队列只用于事后凭证**送达与通知**，绝不用于"先成交、后补单"；
- 锁单即锁版本（事后改约不溯及在途）；消费单幂等（重放去重）；净额头寸的"检查—扣减"原子串行，并发触顶按先到先得确定性拒绝；
- **协议解除**：生效 → 任一方发起终止 → 冷静期（停接新在途、已有锁定单到期完成或回滚）→ 最终净额结算（双方对净额签字）→ 归档。可单方面停止未来，但**已签名的净额债务不可单方否认**；拒绝最终平仓则该双边额度锁零、转争议，不波及其它双边协议；
- **占用攻击防护**：锁定即占用对方额度，故设单笔 / 单邻锁定上限、锁定时长硬顶（超时自动释放）、锁定超时率拉低被选径优先级、禁止无真实消费单的空锁——免费中转不等于允许免费占坑；
- 失败给出**确定性原因码**（无路径 / 净应收触顶 / 发行方不可达 / 超预算 / 余额不足 / 锁冲突），客户端据此分别引导重试、换路径或建议直接签约。

## 规模模型：亿级组织，单节点负载为何近乎恒定

直觉类比（邮政分层）：不要求每个邮递员记住全国地址，而是按"省→市→街道→小区"转发。横跳 = 同小区串门、3 跳封顶；层跳 = 寄到外地，沿行政层级上行到共同上级再下行，经过的层数只等于层级深度，与全国总人数无关。

两条**架构不变量**：

1. 禁止任何需要全网扇出的经济操作（经济消息一律双边或限跳）；
2. 跨层只传可验证摘要、不传明细（默克尔聚合，可抽样核验、造假可证）。

**状态局部性第一判据**：任何新特性，单节点的状态 / 计算 / 通信只允许依赖"自身度数 + 常数跳邻域"，一旦依赖全网规模就打回重做。递归共同体树同时是治理、路由、清算、中继四层结构，因此亿级规模下普通网关的负载仍近乎恒定。

## 消费隐私：信息分割

一笔消费含四类信息：买家是谁、**买了什么**、金额、在哪个组织买。可见性按"交付所必需"最小化：

| 信息 | 受理方 D（交付方） | 发行方 A（成员所属组织） | v2 中间方 |
| --- | --- | --- | --- |
| 买家身份 | 可见（交付必需） | 可见（要知道扣谁的账） | 不可见 |
| **消费内容** | **必然可见（交付的物理极限）** | **不可见**（只需核销金额） | 不可见 |
| 金额 / 对手方 | 可见 | 可见 | 只见相邻跳金额 |

- 消费单分两半：**核销指令**（买家、金额、对手方、幂等号）供发行方签名；**交付清单**（内容明细）只在买家与受理方之间端到端。发行方签的是"同意为其成员核销 X 额度"，不需要、也拿不到消费内容；
- **诚实承认物理极限**：受理 / 交付方必然知道内容（看病时医生不可能不知道病情），技术消除不了；系统保证的是**内容不回流到买家所属组织、不进入网络账本**——医疗、照护、求助等敏感服务的隐私价值正在于此；
- **三层澄清**：对外（跨组织 / 对平台 / 对外部观察者）是**假名**系统（公钥哈希、不绑真名、传输加密、无中心全局图谱，近似匿名）；对内（成员与其所属组织）是**记名**的（组织为核销、防超发必然掌握"谁在何处核销多少"，加入即知情同意）；**假名不等于匿名**（长期固定标识的行为图谱可被关联去匿名，敏感场景靠"内容不回流组织"保护）；
- **记账主体自选**："对内记名"以**记账组织**为界——加入任何组织时，"该组织可见你跨组织消费的对手方与金额"必须明示知情同意；不想让某组织看到轨迹的消费，可以改用另一个组织发行的积分（包括只含自己的叶组织）——选择权始终在成员自己手里；
- **不做匿名电子现金**：盲签名与记名、防超发、集体评议相冲突，且触碰金融监管红线；系统外的法币 / 现金交易不归本协议。

## 边界（这一篇不做什么）

- 不做货币兑换、外币钱包、交易撮合与行情；
- 不垫券、不持仓、不做交易对手、不收路由费；
- 不做离线 / 脱机授信消费（实报实销，发行方不可达即失败）；
- 不做匿名支付，也不审查双边协议内容（只要求强制披露）。
