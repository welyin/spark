# 公共议题：一个没有运营方的"去中心化 GitHub"

> 状态：定稿 ｜ 分册：第三层 · 事务
>
> 上游：`wiki/product/public-topics.md`、`wiki/protocol/community/affair-metadata.md`

## 一句话

把一个事务的"**公开发布**"开关打开，它就进入全网公共目录：任何人都能发起、能被全网模糊搜索发现、能承载代码 / 文件 / 讨论 / 决议的完整协作——但没有中心服务器、没有平台账号、数据不属于任何运营方，因此**删库、封号、限流都不存在**。它就是[事务模型](affair-model.md)在全网范围的公共面。

## 解决什么问题

今天的开源项目、社区倡议、公共事务只能寄生于中心化平台，带来三个结构性问题：平台可单方面处置你的项目（删库 / 封号）、垄断发现权（排序 / 推荐 / 可见性）、数据不可核验（只能信平台没改过）。公共议题用 Spark 底座 + 事务体系，把"发起一个公共项目"做成不依赖任何运营方的一等能力。

## 发现：搜索只认标题、简介、标签（产品承诺）

- **全网搜索只索引标题、简介、标签这三样**；讨论正文、文件内容**不进**公共索引；
- **indexer（索引节点）**订阅元数据面、建索引、提供搜索与健康信号，**任何人都能运行、用户可一键切换**；桌面全节点也可自建本地索引、完全不依赖任何 indexer。健康信号 = 从本地事务日志**确定性复算**的统计（活跃参与者趋势、采纳集中度、异议与被申诉次数、最近活动时间、分叉谱系），任何节点复算结果一致，indexer 无法编造，呈现方式由客户端竞争；
- 匹配与聚合是**内核确定性函数**：同一索引状态 + 同一查询，任何节点返回逐字节一致的结果——换 indexer 只换可用性与覆盖范围，**不存在排序操纵**；议题数量无上限，indexer 可按区域 / 主题分工覆盖子集，轻客户端并行查询多个；
- **不做全局唯一可读名**（不搞 `spark/abc` 这类可抢注短名，短名只是本地显示），议题靠搜索和分享链接发现——抢注是需要共识层才能解决的问题，这里直接绕开。

## 两面：轻元数据全网复制，重内容按需拉取

- **元数据面**（标题 / 简介 / 标签 + 内容指针）全量复制给 indexer；**内容面**（Git 仓库、文件 blob）内容寻址、按需拉取，不随元数据全量扩散；
- **Git 直接复用，不发明协议**：仓库经文件同步分发为**只读镜像**（Git 对象本身内容寻址）；本地 git clone 自便，改动走 PR 流程（子事务 + bundle / patch 附件），维护者合并后同步分发；一个议题可引用一个或多个仓库；
- 文件区遵循"**持有即做种**"：任何持有副本的节点自然响应拉取（手机叶子除外），退出议题即停止做种；
- **冷门文件在无人持有时可能暂时下载不到**——必须如实告诉用户，这里不承诺中心化网盘式的永久在线。

## 组织公开名片

组织可发布一张**签名的公开名片**进入公共目录，字段逐个可选（默认仅名称 + 简介；可选成员组织注册表、公开议题列表、联系方式等），**公开到什么粒度由组织自己决定**。

## 参与与治理：完全复用事务体系

参与门槛由每个议题的规则自定义、平台不设任何默认值；参与阶梯、公开履历、上下文 / 公共身份、生命周期、执行核查、事务引用、申诉分叉全部沿用 [affair-model](affair-model.md) 与 [governance](governance.md)，本篇不重复定义。

- **行政区域标签**（如标准行政区划代码）仅用于检索与聚合，**不代表该区域任何机构的认可或参与**；若某机构未来真的采用，它可以成为一个真实共同体域——那是可选增强，不是前提。

## 客户端可替换：数据属于议题，不属于某个插件

- 论坛界面、Git 界面、网盘界面**不是某个官方插件的私有功能，而是开放协议**；任何人都能写自己的议题客户端访问同一份数据，官方插件只是参考实现；
- 其他插件可整体内嵌标准客户端组件（界面 + 存储 + 通讯），而不是层层套壳；
- **换掉任何客户端，数据原样还在**——数据属于议题，不属于插件。

## 与 GitHub 的关键差异（预期管理，必须 upfront）

| 差异 | 用户需要理解的是 |
| --- | --- |
| 无全局唯一名 | 靠搜索和分享链接发现，不靠抢注短名 |
| 删除是"不再提供"，不是全网抹除 | 无人持有副本的议题自然消亡；已扩散内容收不回 |
| 公共身份永久留痕 | 想安静参与就用上下文身份；启用公共身份即接受永久公开 |
| 大文件可用性依赖副本生态 | 冷门文件在无人做种时可能暂时不可下载 |
| 搜索源可换 | 没有"官方唯一搜索结果"，这正是抗审查特性 |
| 身份即密钥 | 丢密钥 = 丢身份，恢复走设备信任体系（见 [identity](../foundation/identity.md)） |

## 自我审查：过滤权在每个节点手里

Spark 没有平台级审核（结构上不存在），但**过滤作为一种能力被拆散到每个节点**——判断归人，执行归确定性：

- **内核不做内容理解**："这是不是该删的内容"没有唯一正确答案，判断永远归人 / 组织 / 插件；内核只提供确定性执行（规则匹配、处置留痕）；
- **个人层**：过滤规则（关键词 / 来源屏蔽 / 内容分类）由客户端与插件实现——规则自己定、插件可替换；拉黑与免打扰是内核能力（见 [communication](../community/communication.md)）。纯本地行为，不影响任何他人的视图；
- **组织层**：组织治理自己的域——折叠 / 移除本域公告与讨论、处置成员内容，走组织策略并受公示延迟禁令约束：处置是组织级动作，必须公示、留痕、可申诉（申诉自指，见 [governance](governance.md)）；事务内主持人另有展示层权限（折叠评论，见 [affair-model](affair-model.md)）；
- **indexer 层**：indexer 可以不索引任何内容——只影响它自己用户的搜索结果，换 indexer 即换视图。

## 边界（这一层不做什么）

- 不做全网内容审核 / 强制删除（垃圾靠"关注才复制"天然限流，加上客户端 / indexer 自行过滤）。**责任落点如实写明**：indexer 运营者对自己索引与呈现的内容负责（过滤只影响自己的视图）；议题发起人与名片发布主体对自己发布的内容负责；违法内容由现实法律途径对接**发布主体**——Spark 不提供、也不伪造一个"找平台投诉"的入口；
- 不承诺冷门内容永久在线、不做全局命名注册、不干预搜索排序与推荐（呈现交给客户端竞争）；
- 不假设任何政府 / 机构在系统内存在或背书。
