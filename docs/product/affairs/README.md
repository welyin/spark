# 第三层 · 事务（Affairs）：一群人如何共同做出可执行的决定

> 状态：定稿
>
> [第二层](../community/README.md)给出了"人的结构"；这一层是让结构**动起来**的发动机。组织的选举、改组、创设，经济的积分发行、红冲、争议授权，全部由事务决议驱动——它是贯穿共同体与经济的横切层，所以独立成章。

## 贯穿这一层的三条原则

1. **内核只管"有唯一正确答案"的部分。** 容器、操作日志、时间先后、计票规则的确定执行由内核保证；而"这是什么类型的事、谁有资格、值不值得通过"全部交给事务类型插件与组织规则（解释权下放，见[插件层](../plugins/README.md)）。
2. **透明是组织级效力的唯一硬约束。** 章程级变更必须公示、延迟生效、留痕（底层不可变）；如何决策——独断还是集体——是组织自己的策略选择，内核只求值、不干预。
3. **诚实区分"能证明的"与"社会性的"。** 系统能保证流程确定、透明、可审计、可离线核验；但不假装替代线下身份核实，也不假装"链上决议 = 链下已执行"。

## 与上下层的接口

- **向下**：用 [存证链](../foundation/evidence.md)固定操作先后与决议、用[身份](../foundation/identity.md)签名、用[共同体名册与凭证](../community/membership.md)判定参与资格；
- **向上**：为经济层提供"积分发行 / 红冲 / 争议授权"的**唯一合法来源**（经济层不接受任何单点指令）；为插件层提供可被类型插件解释的统一容器。
