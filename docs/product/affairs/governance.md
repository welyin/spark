# 治理：集体决策是组织级权力的唯一来源

> 状态：定稿 ｜ 分册：第三层 · 事务
>
> 上游：`wiki/product/community-model.md` §四、§六；`wiki/protocol/community/org-signature.md`、`docs/protocol/org/org-recovery.md`

## 一句话

组织对外行动靠"满足策略的签名集合"；章程级变更必须**公示、延迟生效、全程留痕**（时间以存证链为准）——这是内核唯一的硬约束。至于如何决策——独断还是集体、谁能提议谁能否决——是组织自己的策略声明，内核只做确定性求值、不做干预。这套机制让组织既能自由选择治理形态（包括中心化），又保证任何权力行使都在阳光下、成员始终有反应窗口。

## 组织签名：组织作为一个成员怎么"签字"

组织加入、退出、表态时，用的既不是某个管理员的个人密钥，也不存在一把"组织总私钥"（单点保管无解），而是**满足该组织当前策略的签名集合**：

- 默认"**任一现任管理员签名**"，验证时回查历史名册、确认签名者当时确为管理员；
- 可选 **m-of-n 多签**；
- 可选**门限签名**（分片合成一把对外公钥）——与上两种并列的可选形式，组织策略自选；**硬前提 = 签名者可溯**：只采用可识别门限方案，谁参与了签名必须永远可查，不满足此点宁可不做（设计一次到位，实现排期见 [todo](../todo.md)）。

这一层解决的是**日常代表行为**（加入、退出、表态、邀请成员）；下面的透明与延迟禁令管的是**章程级效力**。

## 透明与延迟禁令（底层不可变，任何组织策略不得删改）

- **章程级效力**——策略修改、换届、创设组织、预算、改组——必须**公示 N 天后才生效**、全程留痕（时间以存证链为准）：没有反应窗口的透明等于没有透明——变更先生效、后传播，"可审计"就成了审计既成事实；
- **决策结构由组织策略自由声明**：谁能提议、公示期内谁能否决、需要多少人批准——独断、多签、正式投票、"延迟生效 + 阈值否决"皆可。内核只按声明的策略做确定性求值，**不干预组织选择中心化还是集体化**；
- **策略可引用插件数据**：资格或权重的输入可以是插件**按契约发布的数据快照**（股权、贡献记录等）。为什么必须是快照而不是直接读：插件数据是"活的"（股权随时转让），求值若读"当前值"，表决期间的数据变动会让不同节点算出不同结果；快照把某时刻的完整数据**冻结成带插件签名与存证锚的不可变发布物**，策略文本引用其**哈希**——如同股东大会的"股权登记日"：以登记日名册为准开会，会后再转让也不影响本次表决权。求值器只验证来源（签名）、完整性（哈希）与时点（快照须早于决议开始），不理解数据语义；插件间的数据流动一律走契约接口（见 [plugin-types](../plugins/plugin-types.md)），**不存在求值器直接读插件集合的通道**。但**内核经济对象**（积分 / 净债权）仍不得作为票权输入（结构封死，见 [economy](../economy/README.md) 三底线；成员出资本就不设内核对象，信息面映射归插件）；
- **小组织推荐默认"延迟 + 否决"**（模板层样本，组织可改）：多签在共同签名者失联 / 丢钥时会死锁，而延迟 + 否决天然带着恢复路径；
- **效力来源必须事先声明**：组织要**事先**写明"本域成员 / 某项规则由某某事务的决议决定"，决议才生效，**不能事后追认**（防治理偷袭）；
- 决议能做的事不限类型：**改组**（直接变更某组织成员）、**创设组织**（新组织的"出生证明"就是选举结果）、修订规则——关键是事先声明 + 策略求值；
- **诚实提醒——权力越集中，钥匙越要看好**：决策结构越中心化，少数密钥承载的权力越大，密钥劫持在一个公示窗口内能造成的破坏也越大——这与物理世界一致：权力越集中的组织越容易被"夺印"。配置中心化决策结构时，系统应明确提示掌权者密钥保管纪律（生物识别解锁、芯片隔离、助记词备份，见 [identity](../foundation/identity.md)）。

## 参与阶梯：挡住水军，但不挡住声音

三级为默认形态（数值事务规则可调）：

| 级别 | 能力 | 获得条件 |
| --- | --- | --- |
| 观察者 | 查看、评论、讨论 | 零门槛，新密钥即可 |
| 贡献者 | 提交正式贡献（议案、文本、数据） | 1 次贡献被采纳 |
| 投票者 | 参与决议表决 | 贡献者在级满约 30 天 + 累计 3 次采纳 + 近 90 天活跃 |

- **采纳本身也是集体决策**（默认延迟 + 否决，重要事项正式投票），没有"维护者单点拍板"；
- **一人一票、不加权**；在级天数由存证链记录推导，批量小号必须"真养"；长期不活跃（默认 90 天）降回贡献者、可重新积累；
- 阶梯挂在**治理上下文**（某项目 / 某域 / 一组关联事务），**不是全局声望分**，防止老号交易；冷启动由创世规则声明初始投票者集合，权力随后来者爬升自然稀释；
- **观察 / 评论层永远零门槛**——阶梯只卡贡献与表决，不卡声音；资历通道始终向上开放；
- 两类资格基础可自由组合：**阶梯回答"你做过什么"，凭证回答"你是谁"**（业委会选举用凭证，开源议题用阶梯）。账龄等能从链上确定性推导的基础件在内核；凭证、担保链、成本类门槛由插件补充——目标是**验证"唯一真实参与者"而不暴露其身份**，让每个假身份都要花时间、花钱或花真实社会关系。

## 透明，是"被捕获"的终极解药

- 协议**不禁止串联**（串通也是参与意志的表达），只保证**透明与可退出**；
- 事务健康信号（活跃参与者趋势、采纳集中度、异议与被申诉次数、最近活动、分叉谱系）由**内核确定性计算**，任何节点可复算，客户端如实呈现、呈现方式自由竞争；
- 一旦被捕获或停滞，任何人可持同一历史发起**继承事务**分叉（见 [affair-model](affair-model.md)）。

## 治理连续性：管理员失联 / 丢钥怎么办

先区分两件不同的事：

- **网络层**的"组织整体失联后找回成员节点"是覆盖网恢复，见 [../foundation/network.md](../foundation/network.md)；
- 本篇处理的是**治理权不锁死**。

其机制是：

- 日常"任一管理员签名 + 集体决策可更换签名集合"，不依赖全员同时在线；
- 门限方案下，剩余不少于门限数的分片持有者可协作**刷新分片**（对外公钥不变、旧分片作废、新管理员获得新分片，与换届同构）；低于门限的彻底丢失在数学上不可恢复，只能靠参数冗余（如 3/5 容忍 2 人失联）与"集体决策更换签名集合"兜底——**钥匙是耗材，策略才是本体**；
- 小组织用"延迟 + 否决"自然恢复，不需要多签仪式；
- **现实信任锚**：协议能保证流程确定、可验，但"某成员对应真实身份 / 真是业主"是社会事实，靠验证插件与线下核实（见 [../community/membership.md](../community/membership.md)），技术到此为止。

## 申诉与主持人边界

- 对决议的异议 = 引用它发起新事务，走同一套集体决策（申诉自指）；**Spark 不内置争议仲裁程序**，仲裁如何组织是组织与插件的事；
- 事务主持人（发起人）只有展示层权限，规则修改必须走集体决策。

## 边界（这一层不做什么）

- 不提供绕过公示与延迟的即时生效通道，也没有"平台方强制改组"之类的超组织权力；
- 不做全局声望分 / 人品分；不替组织判定成员资格；
- 不兜底链下执行（决议 ≠ 已执行）；
- "公示 + 延迟生效 + 留痕"是**不可变底层逻辑**，任何组织策略都不得删改；决策结构本身永远是组织可配置的策略。
