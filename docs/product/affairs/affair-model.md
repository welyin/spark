# 事务：只有发起人、没有归属的公共容器

> 状态：定稿 ｜ 分册：第三层 · 事务
>
> 上游：`wiki/product/community-model.md` §六；`wiki/protocol/community/affair*.md`

## 一句话

事务（议题）是系统里"一群人共同处理一件事"的**通用容器**：它不属于任何组织或个人，只有发起人；**谁关注它，谁就持有一份副本，只要还有副本存在它就不会消失**。选举、预算表决、联署、纯讨论……都是套在同一个容器上的不同"类型插件"——内核不认识"选举"，只认识容器。

## 为什么事务要独立成一层

它是全局一等公民：组织的创设、换届、改组靠事务决议；积分的发行、红冲、争议授权也来自事务。它不专属于某一个域——**域不拥有事务，只有一面"事务墙"**（按成员关注与资格过滤呈现的视图）；组织通过引用事务 ID 来声明"我的这项变更以那个决议为效力来源"。

## 容器与"两面"：骨架很轻，重内容在外

- 内核只定义容器：发起人、规则、操作日志、决议存证；**类型由插件定义**（选举 / 预算 / 讨论……），**内容由插件承载**（选票、帖子、文件），全部作为签名操作进入日志；新增事务类型不需要改内核；
- **元数据面 vs 内容面**：标题、简介、标签是元数据面（全网搜索只索引这三样，这是产品级承诺）；讨论正文、代码、文件是内容面，**按需拉取**，不随元数据全量复制。

## 复制：关注即副本

- 事务一旦发起，关注它的人 / 组织就持有副本；**无人持有副本的事务自然消亡**，删除只有一种语义——"不再有人提供"；
- **例外层——决议结论永锚存证链**：已产生组织级效力的事务（换届、改组、预算等），其决议**结论**（结果哈希与签名）锚定该组织存证链，内核保证效力可追溯，**不随事务本体消亡**——存证链是组织数据，由该域全员数据节点保存（承接 [membership](../community/membership.md) §四）；事务**本体**的去留由组织自选（关注即保留 + 可选保留策略），不设强制副本。于是"为什么这么改"永远可查，哪怕本体早已无人持有；
- 垃圾事务因此天然不扩散（不关注就不复制），系统不设全局发起门槛；需要门槛时由该事务自己的规则声明（见 [governance](governance.md)）；
- 公共事务的长期副本持有者，天然是索引节点 indexer（见 [public-topics](public-topics.md)）。

## 生命周期

```
发起（写明关闭规则）→ 进行（签名操作累积）→ 达标自动决议 →〔执行型：待执行 → 回报 → 核查〕→ 关闭
```

- 创建时写明关闭规则：截止时间、法定人数、通过阈值，达标即**自动**产生决议；中止必须走集体决策；
- 默认任何成员可发起，域可用策略收紧；公共事务任何人可发起；
- **规则一旦发起，修改只能走该事务自身的集体决策**，每次修改都是签名操作、留痕可验——发起人单方不能改；
- **主持人 = 发起人，权限仅限展示层**（折叠评论、提议修订标题 / 简介 / 标签）；元数据修订按"延迟生效 + 阈值否决"生效、留痕，防止操纵发现面；主持人失能或滥权由申诉事务处置。

## 两条确定性硬规则

- **时间权威**：关闭、公示等时间条件一律以[存证链](../foundation/evidence.md)时间戳为准，不采信任何单机本地时钟——否则不同节点会判出不同结果、副本分裂；能写成顺序条件（如"收到第 N 个有效操作即关闭"）就优先写顺序条件；
- **法定人数快照**：参与基数以投票 / 决议**开始前**的有效名册快照为准，防止窗口期靠拉人 / 踢人操纵计票。

## 参与者身份：一律是个人，组织只"表态"

- 公共事务的参与者一律是**个人账号**：组织不爬阶梯、不表决，只可发布满足其签名策略的"表态"作为展示级立场，不产生票权。**域内事务不同**：参与资格由该域规则与凭证决定——如业委会选举中投票单位是"户"（家庭组织按户一票，见 [model](../community/model.md) 阳光小区例）；
- 两种参与身份，用户自选：
  - **上下文身份（默认）**：按治理上下文派生、跨事务不可关联，适合安静参与敏感议题；
  - **公共身份**：一个稳定公开账号，其全部参与构成**公开履历**。启用即明示"此身份下一切参与永久公开"，已扩散履历不可收回；
- **公开履历三原则**：只载可验证事实（原始统计、经集体决议背书的裁定记录、事实时间线）；**不接受任何人给他人贴标签**；**不计算人品分 / 信用分**（分数可刷、可交易、可被政治化）；成败中立陈列，由查阅者自行判断。

## 事务引用：四种关系，一套机制

携带目标事务 ID + 关系类型：**继承**（换代）、**申诉**（异议）、**父子**（分解）、**关联**（导航）。谱系由索引层重建展示；父子只做引用、**不做状态耦合**（父决议不由子决议聚合）。

- **申诉自指**：对一份决议有异议，就是引用它发起一个**新事务**，走同一套集体决策与存证，不另设平行申诉 / 仲裁机构；
- 被劫持、被停滞时，任何人都可基于同一份历史发起**继承事务**（显式引用前任、谱系公开）——透明分叉是终极救济。

## 执行边界：决议 ≠ 已执行

- 决议的效力**止于链上状态变更**（名册、策略、存证）；链下执行（预算实际拨付、物业实际动工）是社会性的；
- 执行型事务由执行方签名回报状态（已受理 / 执行中 / 执行完毕 + 佐证材料）；核查方式由事务规则声明，默认"执行完毕公示 N 天、无阈值异议即核查通过"，也可指定核查方签名或正式投票；核查不通过则打回或转申诉；
- 产品**如实呈现"决议 ≠ 已执行"**，不假装在链上闭环。

## 事务无秘密、一切可审计

- 容器是参与者共同处理的公开对象，参与凭证之内人人可读，**不做内部保密**；类型级保密（无记名投票、密封投标）由对应类型插件自行实现（如计票密钥），平台只见密文；
- 真正需要小圈子保密的事，正确做法是**专门建一个小组织**在其中处理，而不是在事务里藏；
- 决议、选票、名册变更全部形成链式存证，可用独立核验工具离线核验（承接 [evidence](../foundation/evidence.md)），并可导出为线下机构要求的格式、由人线下对接。

## 边界（这一层不做什么）

- 内核不内置任何具体事务类型（选举、账本都是插件）；不设全局审查或强制删除；
- 不做父子状态的自动聚合；不替组织做资格判断；
- 不做平行申诉 / 仲裁程序，也不保证链下执行落地。
