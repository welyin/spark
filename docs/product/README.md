# Spark 产品文档

> Spark 是一个**无中心服务器的协作与共同体操作系统**：你的数据只存在自己的设备上；人们自下而上结成不产生层级权力的组织；以可验证的公共事务进行决策与行动；并在其中运行一套去资本化的互助经济。

本目录是 Spark **干净的产品说明书**：讲清楚"是什么、为什么、规则与边界"，面向想理解、使用或参与建设 Spark 的人。

## 二、文档结构：四层主线 + 一条正交轴

Spark 的业务能力沿一条递进主线展开：**物 → 人 → 事 → 价值**（四层）。另有一条**正交轴**——插件：它回答"谁有权定义这一切意味着什么"，贯穿四层每一处需要"解释"的地方。层间接口与正交轴在 [product-map.md](product-map.md) 中定义。

### 每一篇要回答的核心问题（写作蓝图）

**顶层**
- `vision.md`：Spark 要解决什么问题——为什么"数据在服务商手里"是不可接受的信任假设？它是什么、明确**不是什么**（非目标：不做公链/不做加密货币/不做内容审核平台）？为什么第一验证场景是业委会投票 + 街道办存证？目标用户与典型场景？
- `product-map.md`：四层 + 正交轴全景、层间咬合、横切机制、统一术语（即本篇地图）。
- `roadmap.md`：从协议内核到自举到第一验证场景分几阶段、当前到哪？v1 最小闭环、v2、远期各放什么？什么是"用 Spark 开发/发布/分发 Spark"的自举？

**foundation/ 底座**
- `personal-data.md`：没有中心服务器，数据存在哪、多设备如何靠向量时钟一致同步？一台设备损坏/离线为什么不丢数据（副本、持有即做种）？大文件如何分块、配额与自动清理如何运作、P2P 下"删除"到底意味着什么？个人/家庭/组织数据如何在结构上分开又可靠保存、如何整体导出？
- `identity.md`：没有平台账号，"我是谁"如何由 RootID 自证？为何每域派生独立身份、跨域不可关联？新设备授权、生物识别解锁、设备撤销如何工作？丢钥/忘口令如何靠延迟恢复与备份二维码找回、改密为何要"全账号换锁"？
- `network.md`：跨网设备如何 NAT 打洞直连、打不通如何经 DHT 重寻址？中继如何工作、为何是可自由定价的协议外服务？手机为何是"叶子"、后台如何保活推送？跨组织离线时凭证靠什么送达（网关邮箱/orgq）？
- `evidence.md`：关键数据如何形成只增不减的链式存证、锚定在什么上？如何导出离线核验包，让没装 Spark、不联网的一方（如街道办）也能独立验证签名与完整性？存证与同步是什么关系？

**community/ 共同体**
- `model.md`：为什么"个人只加入叶组织、组织才能加入共同体"？个人空间/叶组织/共同体域三层各是什么？为什么加入不是吞并、层级不产生权力？成员关系 DAG 如何禁环？需要独立边界时如何"分组→升格"、为什么不支持分裂？
- `membership.md`：邀请、认领、加入、退出各走什么流程，退出为何"人可以走、事实不走"？名册跨组织可见有哪几档、字段级可见性如何控？托管域×公开发布、读授权门禁如何做到"离队即失效、零密钥轮换"？共同体数据由谁的设备保存、K 副本底线与移动叶子如何平衡？
- `communication.md`：去中心化下 1:1/群聊、消息状态、应用会话（服务号）如何成立？为什么所有 DM 共用一套 E2E 加密 + 离线密文暂存 + 多设备寻址底座？通讯录（好友/标签/拉黑）如何无中心账号运转、通知如何到达？（朋友圈等业务插件不属内核，清单见 `plugins/catalog.md`）

**affairs/ 事务**
- `affair-model.md`：为什么事务"只有发起人、没有归属"、关注即副本如何使其无法被单方删除？事务容器与元数据面/复制面如何分工？从发起到关闭的生命周期、时间为何以存证链为准、法定人数为何取开始前名册快照？事务间如何以继承/申诉/父子/关联引用？
- `governance.md`：组织对外行动时谁的签名有效（任一管理员 / m-n 多签 / 门限签名）？为什么"公示+延迟+留痕"是底层唯一硬约束、决策结构（独断到集体）为何下放给组织策略？参与阶梯如何既防水军又不卡声音？决议如何自动改组/换届/创设组织（效力须事先声明）？管理员失联/丢钥时组织如何恢复、治理如何连续？异议为何以"引用旧事务的新事务"申诉？
- `public-topics.md`：事务如何打开为全网公共议题（去中心化 GitHub）？indexer 是什么、为什么匹配是确定性函数、换索引源不会被操纵？全网搜索为何只索引标题/简介/标签？代码与文件内容面如何按需拉取、持有即做种？组织公开名片如何发布、与 GitHub 的关键差异和用户预期是什么？

**economy/ 经济**
- `README.md`：什么是 W—G—W / G—W—G′？宪章层/政策层/模板层如何分工？内核边界的"唯一正确答案"判据是什么？
- `credits.md`：积分为什么是记名劳动凭证而非货币、为何兑付即销毁、个人层不流通？发行如何经集体决策事务授权、序列号状态机与发行恒等式如何防超发？兑付端最小机制（兑付单/三类供给/供给声明）如何成立？当期分配与永久贡献档案为何分立、不可分割储备与公共扣除如何运作、成员出资为何只是有限定息的内部资本账户？退社/主体消亡/时效/红冲/兑付紧张如何处理？
- `inter-org.md`：为什么双边协议是"相互受理"而非兑换、一笔跨组织消费的四方账目如何流？v2 代理链如何"信息沿链传、信用不沿链传"且路径免费？横跳/层跳双预算如何让亿级规模下清算仍可行？实报实销为何禁止离线赊账？消费隐私如何在受理方/发行方/中间方间分割？
- `fiat-compliance.md`：为什么不隔离法币、允许登记经营纳税，却严禁积分对私兑现、不挂汇率？防收编四闸门是什么、顺差只允许哪三个去向？封闭成员记账的合法形态与红线（不面向公众、不设资金池、积分非工资、视同销售涉税）是什么？
- `capital-defense.md`：11 条资本回归路径中哪些能被内核【结构】封死、哪些只能【证据】照亮、哪些纯靠【治理】？单组织破产为何不拖垮全网（硬额度/敞口透明/有序出清/损失自担）？健康度与相关性风险为何只给确定性指标、不替组织决策？本设计在劳动券与合作社谱系中的理论坐标与自觉边界是什么？

**plugins/ 解释权（正交于四层）**
- `README.md`：为什么说插件处理的是"解释权"——Spark 如何把"这意味着什么、这算什么"的定义权从中心开发者手中去中心化、下放到每个组织？
- `interpretation.md`：哪些是内核绝不能让渡的机制（防伪/状态机/恒等式/公示延迟禁令），哪些语义可下放？声明式策略引擎如何做到"插件只出策略文本、内核引擎在读取点评估并静态查冲突"？为什么解释必须三级公开、可替换可分叉、换插件不动数据？
- `plugin-types.md`：四类解释对象如何贯穿四层——事务类型（选举/预算/账本）、资格验证（"谁是业主"，插件是方法、验证人才是信任）、经济规则包、应用/视图插件？四类各举最小示例，具体需要哪些插件见 `catalog.md`。
- `catalog.md`：按"自举""小区自治"两个里程碑各需要哪些基础插件？每个只登记**名字、功能说明、状态（计划 / 开发中 / 已开发版本）**；内核内置能力（DM 底座与通讯录数据 / 存证 / 文件同步（Git 仓库分发复用） / 分发）不在其列，docs 不写插件实现。
- `runtime-and-trust.md`：插件在 iframe 视图沙箱与 QuickJS 后台沙箱如何运行、数据 API（declareCollection）边界在哪、插件间如何互操作？为什么"开源仓库写权限即签名能力"、作者无需自管私钥？安装通路信任级 L0 侧载 / L1 仓库锚定 / L2 官方签名如何区分、验证类为何必须 ≥ L1（L0 拒装）、为何不设官方审核名单？应用如何仓库锚定安装、镜像多市场、本地验签、非管理员请求安装？客户端为何可整体替换/内嵌、数据不属于插件？

## 三、docs 与 wiki 的分工（重要）

| | `docs/`（本目录） | `wiki/`（工程知识库） |
|---|---|---|
| 回答 | 是什么、为什么、产品规则与边界 | 怎么实现：协议字节规格、架构、代码评审、测试、UI 定稿、排期 |
| 读者 | 使用者、认同者、潜在贡献者 | 开发者、架构师 |
| 稳定性 | 稳定、成体系、对外可读 | 随开发快速迭代，含大量过程记录（fix/review/cosign） |
| 关系 | **只链接 wiki，不复制实现细节** | 事实以 wiki / 源码为准 |

- 一处产品事实只在一个地方权威定义，其余地方链接过去，避免双份维护漂移；
- `economy/` 的母稿是根目录《共同体经济系统设计.md》（v0.10）：**完整单页版在根目录原地保留**，`economy/` 五篇是其结构化分册，内容口径以母稿为准。

## 四、写作约定

1. 每篇开头用一句话回答"这篇讲什么"，再展开；
2. 只写产品逻辑（是什么、用户看到什么、规则边界）；实现与协议细节用链接指向 wiki；
3. 概念用词一律以 [product-map.md](product-map.md) 的术语表为准，不新造同义词；
4. 单篇聚焦一组问题、控制篇幅；文首标注状态：`草稿` / `定稿`；
5. 保持"机制与政策分离"的克制：内核只做有唯一正确答案的事，价值选择归组织（详见 economy 总纲，此原则全产品通用）；
6. **不记录任何插件的具体实现**（运行时、协议、SDK 归 wiki）；插件只在 [plugins/catalog.md](plugins/catalog.md) 登记名字、功能、状态三列，AI Bot 等一律视为普通插件，不单独成章。内核内置能力（DM 底座与通讯录数据 / 存证 / 文件同步与分发）不在插件清单之列。
