# 递归共同体：个人属于家庭，家庭属于楼栋，楼栋属于小区

> 状态：定稿（2026-09-10 修订：组织/共同体合并决策，替代原「唯一成员规则」）｜ 分册：第二层 · 共同体
>
> 上游：`wiki/product/community-model.md` §一–五、十一、十二；`wiki/architecture/identity/organization.md`

## 一句话

**组织是唯一概念：组织可以包含组织和个人，是否包含个人由组织自己在创世策略中声明。** 于是"个人 → 家庭 → 楼栋 → 小区 → 街道联合体"构成一张可多父、可嵌套但绝不成环的有向无环图（DAG）；每层的公共事务由这层自己治理，每层的数据由这层成员（个人或组织）的节点共同保存。

**术语**：合并后统一称"组织"；"共同体"保留为对"成员含组织的组织"的习惯称呼（楼栋、小区这类共同体域，仍是组织的一种形态）。

## 为什么需要：单个组织是孤岛

一个真实小区不是一个组织能装下的：十栋楼各是一个组织（管楼内事务），物业、业委会、兴趣小组各是组织，而"**小区本身**"是这些组织的集合，还有自己的公共账目、公告和公共事务（比如选业委会）。单组织模型表达不了"小区"——它既不是某个组织的子集，也不是一份无主名单，它是一个真实共同体，有自己的数据和治理过程。

## 三层形态与成员类型声明

| 形态 | 成员是谁 | 例子 |
| --- | --- | --- |
| 个人空间 | 无成员概念，纯私域，**不是组织**，不与家庭混同 | 你自己的个人空间 |
| 叶组织 | 默认仅**个人**（由创世策略声明） | 家庭、兴趣小组、两人工作室 |
| 共同体域 | 默认仅**组织**（成员含组织的组织，习称"共同体"） | 楼栋、小区、街道联合体 |

**加入门槛 = 创世策略声明**：组织在创世时声明本域接受哪些成员类型（仅个人 / 仅组织 / 两者），内核只做验证。默认模板维持现状——叶组织声明"仅个人"、共同体声明"仅组织"，存量内容零迁移；声明"两者"的组织同样合法（如小区直接接收热心业主个人）。

**成员分两类：个人成员 / 组织成员。** 组织可嵌套——组织作为成员加入上层组织；加入小区的实体仍可以是"家庭组织"这个**户**。**计票权重是纯凭证 / 规则问题**：平台不预设一人一票或一户一票，"按户一票"由组织的规则 / 资格插件表达——这比"结构白送"更自洽：资格本就跟着凭证走（见 [membership](membership.md)），结构不必替规则下结论。

配套：

- 一个人可同时属于多个组织（自己的家庭 + 摄影小组）；
- 一个组织可同时加入多个共同体（成员关系是 DAG，**没有单父约束**）。

## 几条不可变的结构规则

- **加入不是吞并、层级不产生权力**：加入共同体是"参与公共生活"，本域数据边界原样不动；上级不自动获得下级内部的任何权力，下级也不让渡权力。上级影响下级的唯一通道，是"承认 / 撤销承认"与共同体决议的既定效力；
- **禁止成环（底层不可变，任何组织策略不得覆盖）**：A 加入 B 之后，B 不得再加入 A——加入操作在验证时沿成员关系图做环检测，**含多跳间接环**（A→B→C 之后 C 同样不得加入 A），成环即拒绝；
- **子组织 vs 分组**：需要独立数据边界 / 独立治理 → 子组织（独立域）；仅为管理便利 → 分组（父域内的标签，无数据边界）。中间层（楼栋 / 单元 / 楼层）可有可无、可任意多层；
- **以"升格"代替"分裂"**：分组可经一次事务决议升格为子组织；**不支持真正的分裂**——公共历史是只增不减的签名记录，楼内事务与公共事务交织，技术上拆不开、法理上也不该让某栋楼把全体投票的结果带走。规则是"**升格不分旧账**"：共同体内产生的历史留在共同体，新域从创世块开始；
- **退出留史、域不可解散只可退出**：组织退出共同体后，它在共同体里产生的历史原样保留（共同体数据属于共同体，不属于任何成员）；全体成员退出后该域成为**空域**——只读历史档案、无人能写，由仍持有副本的节点继续保存；**空域历史无人兜底**——最后的持有者清理或离线后即自然消亡，留史承诺以"有人持有期间"为限；在乎历史的人可自愿持有副本承接（例如专设历史档案组织），内核不设托管规则；上级可经自身治理流程移除失能成员条目；
- **创建者默认值**：创建者自动成为首任管理员；当成员数超过 1，策略修改默认改走"延迟生效 + 阈值否决"，让组织从单人管理平滑过渡到集体决策；
- **成员身份派生**：每加入一个域就派生一个该域专属身份，跨域不可关联（承接 [identity](../foundation/identity.md)）；组织可自行选择公开 orgId 以便公示识别（如业委会、物业本就需要公开）。

## 组织如何"作为一个成员"行动：组织签名（概览）

组织加入、退出、表态时，签名方既不是某个管理员的个人密钥，也不存在一把"组织总私钥"（单点保管无解），而是**满足该组织当前策略的一个签名集合**。注意：组织签名解决的是**日常代表行为**（加入、退出、表态、邀请成员）；章程级效力（策略修改、换届、创设组织等）另受公示延迟禁令约束——必须公示、延迟生效、留痕，决策结构由该组织策略声明（见 [governance](../affairs/governance.md)）。

- 默认"任一现任管理员签名"，验证时回查历史名册、确认签名者当时确为管理员；
- 可选 m-of-n 多签、门限签名（硬前提 = 签名者可溯，只采用可识别门限方案，见 [governance](../affairs/governance.md)）；
- **orgId = 创世策略记录的哈希**，自认证；验证上层声明只需验证直接相邻层的策略，不沿嵌套链下挖——验证成本与共同体深度无关。

> 决议如何产生组织级效力、公示延迟禁令、换届与恢复，属于治理机制，见 [../affairs/governance.md](../affairs/governance.md)。

## 一个完整例子：阳光小区

1. **组建**：创建"阳光小区"共同体域（默认模板声明"仅接受组织成员"），邀请十个楼栋域、物业域加入，各域按自己的签名规则接受、进入小区名册；若小区策略声明同时接受个人成员，热心业主也可以个人身份直接加入小区；
2. **公共生活开始**：有了公共公告栏、公共账本、公共议事区；
3. **发起选举事务**：规则写明"按户一票、候选人资格、投票期 7 天"；
4. **投票**：各家庭组织投票——按户一票由选举规则与户凭证表达成立；
5. **自动换届**：业委会域**事先声明**过"本域成员由小区换届选举决议决定"，决议生效即新旧交接，无需人工操作；
6. **从无到有**：若原本没有业委会，决议可以直接创设它，"出生证明"就是全体业主的选举结果；
7. **公开透明**：业委会工作记录托管在小区层、对全体成员可读可核、对互联网不可见。

## 现实信任锚（必须对用户讲清）

协议能保证每个"户"的票真实、规则被遵守、全程可核验；但"**这个家庭组织对应一户真实人家、确实是业主**"是一个**社会事实**，靠身份验证与线下核实（见 [membership](membership.md) 的"验证即插件"）。验证凭证与名册公开可审计、录入人与被录入方都留痕，但技术到此为止，不假装能用密码学取代线下信任。

## 边界（这一层不做什么）

- 个人空间不是组织、不与家庭混同，私域双轨保留；
- 不预设计票规则：一人一票 / 按户一票 / 加权表决都由组织的规则与凭证表达，内核不做政治判断；
- 不规定共同体必须长什么样：中间层可省、可多层、可只做标签；
- 不做组织内部的密码学子边界——要隔离就建子组织（保密边界 = 域边界）；
- 层级拓扑不决定参与资格：**资格跟着凭证走，不跟着中间层走**（详见事务层）。
