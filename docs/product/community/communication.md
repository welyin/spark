# 通信：一条端到端的统一私聊底座

> 状态：定稿 ｜ 分册：第二层 · 共同体
>
> 上游：`docs/protocol/p2p/p2p-dm.md`、`wiki/ui/messages/*`、`wiki/ui/contacts/*`、`wiki/architecture/plugins/social-feed.md`、`wiki/architecture/identity/organization.md`

## 一句话

内核只做一件最朴素、却被所有上层功能复用的事：在两个人（或人与自己的另一台设备）之间，建立一条**端到端加密、可离线暂存、多设备可达**的直连消息通道。聊天、好友申请、组织邀请、已读回执、插件通知都跑在这同一条底座上；多人群组、论坛、朋友圈等"多人会话业务"不在内核，由插件复用这条底座实现。**聊天应用本身也是插件**：内核交付的是通道与数据，默认聊天应用（会话列表、消息界面，以及未来的群聊）是一个可整体替换的独立应用——系统接受任何第三方聊天插件，换插件不动消息数据（数据在你的设备上、由内核托管，从不属于插件）。

## 统一 DM 底座：一条通道，多种信封

- 同一条 1:1 通道透明承载：聊天消息、已读回执、撤回、好友申请 / 应答、资料变更同步、组织邀请 / 应答、成员移除通知、新设备与恢复通知，以及供社交插件使用的定向投递；
- 任何新功能需要"给某人发个东西"时直接复用，不再各造一条通道（与 [personal-data](../foundation/personal-data.md) "把同步下沉为统一能力"同一思路）；
- 业务插件可借它投递"应用会话 / 服务号"类消息；这些消息如何呈现在会话列表由聊天插件决定，会话背后的业务逻辑属于各插件，内核只负责把密文送到。

## 端到端加密：默认、强制、不降级

- 所有私聊正文一律**先端到端加密、再上链路**，中继 / 网关只见过路密文；不提供"降级成明文"的开关，以防中间人降级攻击；
- **每条消息用独立临时密钥加密（前向保密）**：单条消息的密钥泄露不影响其它消息；
- 同一对人长期共享一份会话密钥，并在你的多台设备间同步——于是"手机离线期间电脑先收到的密文"，手机上线后照样能解；
- 信封由根身份签名、带时间窗与幂等去重，防伪造、防重放；发送方身份以签名为准，忽略消息体里自报的发送者（防冒充成"我"）。

## 消息的一生：状态、撤回与去重

- 状态流转：发送中 → 已送达 → 已读；失败可手动重发；已读回执只更新你自己发出的消息；
- **撤回只能撤自己发的**（归属校验，任何人撤不掉别人的消息）；撤回是"双方不再展示"，不是物理删除对方存储（与 personal-data 的删除语义一致）；
- 按消息唯一标识幂等去重：网络重传、重复投递不会产生两条消息，也不会重复计未读。

## 离线与多设备：消息会等你，也找得到你任意一台设备

- **对方在线**：直连收发，不经过任何第三方；
- **个人私聊、对方离线**：密文先在发件人设备侧排队，并同步到发件人的其它自有设备，任一台先上线就替你补投；暂存队列有 TTL 与条数上限，避免无界堆积；
- **组织内单聊、对方离线**：由组织网关（全员候选、活跃成员轮流履职的角色）以**密文**代收暂存，对方上线后转发、转发成功回"已接收 / 已转发"；网关也离线则发件人本地暂存重发、按消息标识去重；
- **多设备寻址**：一个联系人的多台设备对内都是可达目标，系统择优直发；"给自己发消息"等于同步到自己的全部设备（不计未读）。
- 中继管"在线但打不通"、网关管"不在线"，职责分工见 [network](../foundation/network.md)。

## 通讯录：个人朋友与组织成员分开

- **通讯录数据是内核级的**：好友关系、标签、拉黑存于你的设备、随个人域同步；通讯录的**呈现与交互**同样可以插件化——系统接受其它通讯录插件，但它们读写的是同一份内核数据，换插件不动人脉本身；
- **两套人脉、两个空间**：个人空间的"朋友"需双向申请确认；组织空间的"成员"关系来自组织、彼此不必是朋友；
- 从组织里把某成员加为个人朋友，仍需双方显式确认（承接 [identity](../foundation/identity.md)：加入组织不自动暴露个人身份）；
- 支持本地标签 / 分组、搜索排序、个人资料面板与权限设置；
- **拉黑独立于好友关系**：可拉黑陌生人，删除好友不自动解除拉黑；个人拉黑与组织内拉黑分别记录。

## 通知与免打扰

- 未读角标、免打扰等是**每台设备本地**的设置，不在设备间同步（承接 personal-data：已读状态是本机语义）；
- App 被系统杀掉后如何借系统通道 / 第三方 IM 收到提醒，见 [network](../foundation/network.md) 的"离线通知诚实边界"——那是可选插件，不是内核承诺。

## 边界（这一层不做什么）

- 内核**不做聊天应用、不内置多人群组 / 频道 / 论坛 / 朋友圈模型**：默认聊天应用是可替换的独立插件（群聊未来在它里面实现，属该插件自身的演进，不进 Spark 里程碑）；论坛、朋友圈等由各自插件复用 DM 底座与组织同步实现（见 [../plugins](../plugins/README.md)）；
- 不做服务端消息历史云存储：历史只在设备副本上，遵循个人同步的"最近窗口"与副本规则；
- 中继 / 网关不接触明文、不做内容审核（类型级管控是组织 / 插件的事）；
- 不保证离线消息无限期留存：暂存队列有 TTL，长期留存依赖双方设备上的副本（呼应 [open-questions](../open-questions.md) Q01 的数据持久性问题）。
