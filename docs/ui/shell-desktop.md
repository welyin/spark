# PC 端外壳：左栏导航 + 多窗口桌面

> 状态：草稿 v0.7 ｜ 分册：UI 设计（v0.5 通讯录/公共议题归位；v0.6 网络状态统一为左栏全局＋上下文条当前空间、不在窗口标题栏重复；v0.7 左栏功能入口统一为"顶级对话框＋遮罩"、桌面窗口只承载业务插件，左栏顺序对齐 L4）
>
> 本篇定义 PC（桌面端）的整体布局与交互。信息架构与内容模型见 [README](README.md)，空间桌面模型见 [domain-space.md](domain-space.md)，移动端对应物见 [shell-mobile.md](shell-mobile.md)。**命名约定**：一级入口对外标签为「空间」（内部称域空间 / 域），其界面形态为桌面。

## 一、整体布局

PC 端是"**左侧常驻导航 + 右侧主工作区**"，主工作区在进入"空间"后成为一块可开多窗口的桌面。

```
┌────────┬───────────────────────────────────────────────────────────┐
│ 左栏   │  顶部上下文条（仅「空间」桌面出现）：〔域名｜我的域内身份〕   │
│ 72–240 │   同步状态 ▾                                               │
│        │┌─────────────────────────────────────────────────────────┐│
│ ⌕ 搜索 ││                                                         ││
│ ✉ 消息 ││                   主 工 作 区                            ││
│ ▦ 空间 ││     （左栏入口＝顶级对话框＋遮罩；空间＝桌面，插件＝窗口）   ││
│  ├个人 ││         空间 = 一块可多窗口层叠的桌面，有顶部上下文条）   ││
│  ├组织A││                                                         ││
│ ▤ 事务 ││                                                         ││
│        ││                                                         ││
│ ─────  │└─────────────────────────────────────────────────────────┘│
│ 当前头像│ （仅空间桌面内出现）桌面任务栏：已开应用窗口图标 + 全局搜索 │
│ 名字    │                                                           │
│ 网络状态│                                                           │
└────────┴───────────────────────────────────────────────────────────┘
```

- 左栏可在"仅图标 72px / 带文字 240px"间折叠，**默认展开 240px**，之后记忆用户的折叠 / 展开选择；
- 左栏顺序自上而下固定为：**搜索 · 全部消息 · 所有事务 · 空间**（L4：事务上移到空间之上，"空间"区块下挂"应用管理"；对外标签"空间"，内部称域空间），不允许插件插队或新增一级项；**所有左栏功能入口点击都开"顶级对话框 ＋ 遮罩"（同搜索，见下条 L12）**，「搜索」即全局搜索浮层（⌘/Ctrl+K）、作为这套形式的统一基准；
- **左栏功能入口统一为"顶级对话框 ＋ 遮罩"（同全局搜索，L12）**：点「搜索」「全部消息」「所有事务」「应用管理」「系统设置」「测试」「我的」「创建 / 加入组织」等左栏入口，统一开一个**顶级对话框**（最高层级，盖住桌面窗口与 Dock）＋ 半透明遮罩并锁定背景；点遮罩 / Esc 关闭，同一入口**单实例**（已开则聚焦、不叠第二个）。它们**不在桌面开窗、也不做整页跳转**；
- **桌面常驻，桌面窗口只承载业务插件**：主工作区始终是当前空间桌面（只随空间切换）；只有在桌面里双击应用图标打开的账本 / 表决 / 文件等**业务插件**才以桌面窗口存在（拖动 / 分屏 / 最小化到 Dock、可并排，详见 §三）。两个**例外不套模态**：点「空间」里的具体空间项＝**切换桌面**；桌面应用图标＝**多窗口**；
- **「我的」不占一级导航位**：左栏底部当前身份头像 ＋ 名字即「我的」入口（点击开**顶级对话框**，L12）；名字下方小字行是**全局网络状态**；身份行右侧**不放「⋯」菜单**（L6：删更多按钮与"切换账号"，退出登录移入「我的」页第一栏末尾的特殊按钮）；系统设置 / 测试同样以顶级对话框打开；
- 「空间」的**二级菜单（个人空间 / 各组织）在宽栏下常驻展示**，不随当前页显隐；点击某空间即切换并进入该空间桌面；**创建 / 加入入口是「空间」行右侧的虚线框「＋」图标**（靠右），点击弹出菜单（创建组织 / 加入组织），二级菜单列表内不再放置单独的创建/加入行；
- **顶部上下文条常驻**（桌面常驻后恒显示：当前域名 + 域内身份 + 同步状态，右侧网络状态）；
- 各入口带未读 / 待办角标：消息=未读会话数，事务=**等我操作**数（不是全部进行中数，避免噪音）。

## 二、左栏功能入口（统一以顶级对话框呈现）

> 我的 / 消息 / 事务 / 系统设置 / 应用管理等左栏入口，点击都开"顶级对话框 ＋ 遮罩"（§一 L12），**不整页跳转、不在桌面开窗**；对话框内只承载外壳与聚合，点进去的详情 / 操作由插件承载。需要与桌面插件并排时，走 §2.4 / §3.4 的"在所属空间桌面内开窗"旁路。「空间」是桌面，见 §三。

### 2.1 我的（顶级对话框，左右两栏）

```
│ 个人数据      │       本机〔完整副本〕 手机〔叶子〕〔撤销〕 │
│ 我的组织 ▾    │                                          │
│ 我的积分 ▾    │                                          │
│ 通知与设置    │                                          │
│ 独立核验工具  │                                          │
└──────────────┴──────────────────────────────────────────┘
```

- 高危操作（改密码、查看 / 导出助记词、撤销设备）聚在"账号与安全"，视觉加重、且按 [identity](../product/foundation/identity.md) 要求强制输密码，不走生物识别；
- "我的组织 / 我的积分"是**跨域聚合列表**：点组织跳到对应空间，点积分账户跳到该域的积分应用，本页不做域内操作；
- "设备与同步"如实展示每台设备是完整副本还是叶子、在线与否、同步是否走中继。

### 2.2 消息（顶级对话框内三栏 IM 布局）

```
┌────────────┬─────────────────┬──────────────────────────┐
│ 搜索 / ＋   │ 会话列表         │  对话 / 应用会话内容       │
│ 筛选        │ 私聊、服务号分组 │  私聊=聊天插件渲染         │
│ 免打扰设置  │ 未读/时间/摘要   │  服务号=卡片流 + 深链按钮  │
└────────────┴─────────────────┴──────────────────────────┘
```

- 消息**只有会话、不内嵌通讯录**：会话列表把"私聊"与"应用会话（服务号）"分组，应用会话以插件为单位聚合（一个插件一个服务号）；发起私聊由搜索 / `＋` 拉起选人；
- 右侧内容区是**插件视图容器**：私聊由当前聊天插件渲染，可换第三方聊天插件、数据不变；应用会话渲染卡片流；
- 卡片上的行动按钮（去表决 / 去兑付 / 接受邀请）一律**深链跳到本体**，不在消息里直接生效；
- 通讯录是各空间里的插件（个人空间＝好友、组织空间＝成员，两套人脉分开、拉黑独立，见 [communication](../product/community/communication.md)），不在消息里开页签。

- 外壳事务列表**只聚合与我相关**；公共议题的浏览 / 发现是空间里的公共议题插件，不在此外壳列表内（[README §4.4](README.md)）；上下文 / 公共身份如何切换也归该类插件，外壳不设全局切换控件。

## 三、空间 = 多窗口桌面（PC 的核心体验）

进入"空间"后，主工作区变成一张该域的桌面，底部出现桌面任务栏。

### 3.1 进入路径与空间切换

- 点左栏"空间"→ 默认回到**最近使用的那张桌面**；桌面顶部或角落有"空间切换器（域切换器）"，可快速跳到个人空间 / 其他组织桌面（模型见 [domain-space §3](domain-space.md)）；
- 从消息 / 事务深链进入时，自动切到对应域桌面并打开相应应用窗口，上下文条同步切换。

### 3.2 窗口模型（对标桌面 OS）

- 双击 / 单击桌面图标打开一个应用**窗口**；同一应用可开多窗口（如同时看两个事务）；
- 窗口可：拖动、缩放、最小化到任务栏、最大化、贴边左右半屏 / 四分之一屏、层叠、关闭；
- 窗口状态（位置、大小、哪些开着）**只在本机记忆**，不跨设备同步（不同屏幕尺寸无意义，见 README 待决项）；
- 顶部统一标题栏：应用名 · 当前域 · 信任级标 · 最小化 / 最大化 / 关闭（**不显示网络状态**，统一由空间顶部上下文条右侧呈现，见下方说明）；
- 跨窗口拖拽：把文件 / 事务卡片拖到另一窗口（如拖进聊天）触发分享；**跨域拖拽弹目标域确认**，守数据边界（规则见 [domain-space §五.2](domain-space.md)）；从操作系统向里拖文件是相反方向，见 §3.6。

> 窗口标题栏只承载窗口操作：应用名 · 当前域 · 最小化 / 布局 / 最大化 / 关闭；**网络状态不在每个窗口重复显示**，统一由空间顶部上下文条右侧呈现。

### 3.3 桌面任务栏与桌面元素

- 底部任务栏：已开应用窗口图标（高亮正在前台者）、全局搜索、应用市场快捷入口（语义＝**为本空间启用**：从本机已装插件挑选挂到当前空间；组织空间规则类走事务立法、视图类走组织策略。拿到代码 / 装卸 / 更新在左栏「应用管理」系统层完成）、回到桌面（最小化全部）；
- 桌面背景上是应用图标，**可自由拖动、放下时吸附到网格**（Pointer 拖动实时吸附到最近网格位，位置按空间本机持久化 `spark:desktop:<spaceId>.positions`；未拖动的图标按网格自动排列）/ 建桌面文件夹；**右键菜单采用光标定位弹层**（参照 ark `showMenu`/`PopupMenu`：fixed 定位到鼠标处、越界向内翻转、遮罩点击关闭），图标右键：打开、固定到任务栏、卸载（卸载＝本机系统层删代码，弹"仅移出本机、不删数据"说明）、查看信任级与权限；桌面空白右键：更换壁纸 / 恢复默认背景 / **排列图标（重置为网格）**；
- **桌面背景默认高级灰**（令牌，深浅主题随组件库变量），允许**把本地图片设为桌面壁纸**（桌面空白处右键 → 更换壁纸 / 恢复默认背景；图片以本机 dataURL 按空间存储，不跨端）；副本健康度等指示收进顶部上下文条的网络状态弹层，桌面角落不再放常驻状态徽标。

### 3.4 典型并排场景（PC 相对手机的最大价值）

> 注：能并排的都是**桌面里的业务插件窗口**；左栏入口（消息 / 事务 / 我的等）默认是带遮罩的顶级对话框，要并排时先把对应事务 / 应用"在所属空间桌面中打开"转成桌面窗口。

- 左半屏"公共账本"、右半屏"预算表决事务"，对账后直接投票；
- 左"文件"、右"聊天 / 事务"，引用材料发起事务；
- 一块屏同时开"签名表决"与"成员名册"，核对资格。

这些场景是 PC 端优先支持多窗口、而手机端单 App 全屏的根本理由。

### 3.5 实现参考：窗口与桌面的状态模型（参照 ark-desktop-main）

仓库内的 `ark-desktop-main` 是与我们**同栈（Vue3 + Vite + TS）且已跑通**的一套 Web 桌面外壳，验证了"应用内模拟窗口"路线可行，作为 §3.2 的实现蓝本。原则：**借交互与状态模型，不借视觉皮**——它是深色拟物、rgb 硬编码，落地时全部换成 [visual-style.md](visual-style.md) 的令牌与 Element 组件。

**(1) 两级状态分离（核心，直接采用）**

- **应用注册表** `apps: Map<appId, AppDef>`，`AppDef = { id, name, logo, 载体, 初始 w/h/x/y }`。载体两种：`url` → 窗口内 `<iframe>`（第三方 / 远程插件）；`component` → 本地 Vue 组件（内置应用）。同一个窗口壳按"有无 url"二选一渲染。对应 Spark：当前空间的插件清单（**本机已安装 ∧ 当前空间已启用**，口径见 [domain-space §4.1](domain-space.md)）就是这张注册表。
- **窗口实例表** `windows: Map<key, WinInst>`，`WinInst = { zIndex, isSmall, dockPoint }`，只记"开着哪些窗、谁在前台、是否最小化"；**位置与尺寸由各窗口组件本地持有**，不进全局表。

> ⚠ Spark 必须改的第一处：ark 是全局单桌面、只一份 `windows`；Spark **每张空间各持一份实例表与一套图标布局**，切空间 = 整体换一桶。且我们允许同一应用开多窗（并排看两个事务），实例 key 取 `(spaceId, appId, instanceSeq)`，而不是 ark 的单例 `appId`。

**(2) 开窗 / 聚焦 / 层级（一套干净算法，直接用）**

- 开窗幂等：同实例已开 → 取消最小化并置顶，不重复开；未开 → 建实例并**级联偏移**（新窗相对上一个 +20px 阶梯，避免完全重叠）；
- 单一前台 `activeId` + 单调递增 `maxZ`：点哪个窗，哪个窗 `zIndex = maxZ++` 置顶；
- 关闭 / 最小化前台窗后，自动在剩余非最小化窗里选 z 最大者激活，不留"没有前台窗"的空窗期；
- 最小化用 `v-show` 隐藏而非卸载，**插件运行态与未保存输入保留**（边填表单边切窗不丢内容）。

**(3) 窗口本体的可复用交互**

- 标题栏拖动（mousedown 记起点 + document mousemove/up，零第三方依赖）；双击标题栏在最大化 / 还原间切换（记住还原前矩形）；
- 八向缩放：四边 + 四角热区，向左 / 上缩放时同步改 x/y（对侧边不动），带最小宽高夹取；
- **iframe 遮罩（最有价值的一处）**：非激活窗、以及拖动 / 缩放过程中，给内部 `<iframe>` 盖一层透明 mask。iframe 会吞掉鼠标事件，不盖就会"点不激活、鼠标划过 iframe 时拖拽卡死丢事件"。Spark 插件正是 iframe，这是必踩的坑，ark 已填平，直接采用；
- 开窗 / 收窗做 0.15s scale 过渡，锚点取任务栏图标位置（Mac 式"从 Dock 放大 / 收回"），时长用动效令牌 `--spark-dur-fast`。

> Spark 要补 ark 没做的：右 / 下边界夹取、**贴边磁吸与左右半屏 / 四分屏**（§3.2 已要求）；并把 mouse 事件升级为 **Pointer Events** 以兼容触屏 / 触控板。**不设同屏窗口硬上限、不自动关窗**，开几个由用户决定，仅在多 iframe 导致内存吃紧时给一条非阻断提示（见 §六决策 3）。ark 里"iframe 固定 1450px 宽再 `transform:scale` 整体缩小"是给不自适应老页面的兜底，**Spark 不采用**，改为要求插件响应式、只保留最小宽度夹取。

**(4) 桌面元素：任务栏（Dock）+ 图标网格**

- 底部居中毛玻璃 Dock，分两段：`固定快捷区 ｜ 分隔线 ｜ 已开但未固定的窗`，每个运行中图标下有小圆点；毛玻璃透明度 / 底色走 `--spark-*` 令牌，不搬它的写死值；
- Dock / 图标点击三态（标准 OS 语义，直接用）：未开 → 打开；已开且在前台 → 最小化；已开在后台 → 置顶激活。右键 → 固定 / 取消固定、从桌面移除；悬停提示用 Element popover，不引入第三方 popper；
- 桌面图标网格：单击选中、双击打开、右键菜单、空白处右键（换壁纸 / 排列）、图标溢出分页并可拖拽翻页；
- **图标布局持久化范式**：ark 用 `{ background, quicks[], apps[] }` 记录"壁纸 + Dock 固定项 + 桌面图标有序列表"，首次进入用默认图标铺一次（`apps_init`）。这正好落地"组织只给默认布局、成员本地各自排布"——**但 Spark 把这份结构存本机（按 `spaceId + 设备`），不上服务器、不跨端**；组织下发的只是"默认 apps 列表"。

**(5) 明确不参考的部分**

- 它的应用 / 插件商店、租户切换、路由权限校验与自有后端 API 强耦合，Spark 不参考（市场、成员资格、能力授权走内核与插件模型）；
- 自写 PopupMenu、全局禁用右键菜单只借模式；菜单一律用 Element 的 dropdown / popover / contextmenu 实现；
- 纯 mouse 事件不覆盖移动端，手机端仍按 [shell-mobile.md](shell-mobile.md) 的全屏 App + 最近任务栈，不与 PC 共用窗口组件。

### 3.6 与操作系统互拖：拖入 / 拖出（OS ⇄ 空间桌面）

支持从 Windows / macOS / Linux 的文件管理器把文件或文件夹拖进 Spark 窗口，完成"外部数据进入某个域"。它与 §3.2 内部拖拽方向相反：内部拖拽是数据在域之间流动（防外泄），OS 拖入是数据首次进入系统（摄取 ingest），边界规则见 [domain-space §五.5](domain-space.md)。

**(1) 三类落点，落点即目标域**

| 拖到哪里 | 行为 |
|---|---|
| 某应用窗口内（文件目录、聊天输入区、事务 / 账本附件区） | 交给该插件：存入当前目录 / 作为待发附件 / 挂到草稿；目标域＝该窗口所属域 |
| 桌面空白处 | 默认导入该域"文件"应用的导入收件箱，toast 可点进去查看或改位置 |
| 左栏某个空间导航项（即使当前停在别的桌面） | 直接投到被悬停的那个域，导航项高亮提示目标域 |

- 拖拽进入窗口即进入"拖放态"：桌面外框高亮一条**目标域名 + 可见范围**（仅自己 / 全体成员 / 成员组织）；经过可承接的窗口 / 导航项时该目标高亮，不可承接处显示禁止光标；
- 松手前用户始终看得到"会进哪个域、谁能看到"——这条优先级高于流畅度。

**(2) 导入预检与摄取流程**

1. 松手后先做**导入预检**：数量、总大小、类型清单、文件夹是否递归、目标域与可见范围，必要时先改目标位置 / 可见范围再开始；
2. **导入组织域时额外明示**"将同步给该域成员 / 其他副本"；导入个人空间不打断；
3. 后台流式复制进该域本地存储、不阻塞操作：显示进度、可取消、按内容哈希去重（同一文件不占第二份）、断点可续；
4. 先落本机副本，组织域再进 P2P 同步队列，并诚实显示"已导入本机，待其他成员设备上线同步"（接 §五）；
5. 导入后归**域存储**而非某插件独占，该域内有权限的插件都能打开（数据属于域）。

**(3) 安全与最小授权**

- 外壳只把"本次被拖中的文件"的临时读取句柄交给目标插件，**拖一个文件 ≠ 授予整盘 / 整目录访问权**；插件读系统文件受信任级约束，L0 插件默认不承接 OS 拖入；
- 可执行 / 脚本 / 不支持类型给风险提示，**任何拖入文件都不自动执行**；超大文件、超量文件夹先警告；
- 不静默、不后台偷导：没有明确拖放动作，不读取任何系统路径。

**(4) 实现要点（Tauri）**

- 走 **Tauri 原生 file-drop 事件**拿被拖项的本机绝对路径，由 Rust 侧读取 / 递归文件夹 / 算哈希 / 流式入库；**不靠纯 Web drag 事件**——Webview 的 HTML5 拖放拿不到真实路径、也无法可靠递归文件夹；
- 拖放态高亮与落点判定在前端，实际读盘 / 入库在 Rust 侧，前端只拿结果与进度，插件 iframe 不直接接触本机路径；
- **拖出导出（第一版就做）**：把域内文件拖到系统文件夹 / 桌面 ＝ 导出落盘，复用同一套拖放态与落点判定。导出是把域数据**解密成一份本机明文副本**，从此脱离域加密与权限体系（成员权限日后被收回也不影响这份、也不再随域同步），松手时如实提示并显示写出进度；组织域文件拖出同样提示"将在本机另存一份明文副本"。

**(5) 手机端等价物**：无拖拽，用系统"分享 / 打开方式"把文件分享给 Spark，选目标域后导入，规则与 PC 一致（落点即域、组织域明示可见范围）。

### 3.7 系统级快捷入口与深链（把空间 / 应用"投射"到操作系统）

默认仍是应用内模拟窗口（§3.5）；在此之上支持把 Spark 内的一个目标**固定成操作系统层面的入口**，跳过"打开 Spark → 进空间 → 开应用"一键直达。可固定粒度：一张空间桌面、一个应用、或一个具体对象（某条事务 / 会话 / 账本账户，由插件声明可固定项）。

**(1) 三种等价形态**

| 形态 | 做法 | 打开效果 |
|---|---|---|
| 系统桌面 / 程序坞快捷方式 | 窗口标题栏 / 任务栏图标 / 桌面图标右键 →"创建系统快捷方式"（可选桌面 / 开始菜单 / Dock），由 Tauri 写入，名称图标用户自定 | 双击：已运行则把单实例拉到前台并直达目标；未运行则启动后路由到目标 |
| 深链 | "复制链接"得到统一寻址 `spark://space/<域>/app/<插件>[/object/<对象>]`（另有 https 形态的 Universal/App Link） | 点击优先唤起已安装客户端并路由；未安装落到轻量 web 引导页 |
| 浏览器 / PWA | 同一深链在浏览器打开，或装为 PWA 在独立窗口打开 | **完整体验以客户端为准**（密钥、P2P、本地副本都在客户端）；纯浏览器标签只保证受限 / 只读 / 引导，不假装等同 |

**(2) 路由与单实例**

- 外部唤起（自定义协议 / https 关联 / 启动参数 / 快捷方式）全部走**同一条深链路由**：先切到目标域桌面、再打开对应应用窗口或定位到对象；
- 客户端**单实例**：任何外部唤起都聚焦唯一运行实例、不重复起进程；
- 插件可声明"可固定目标"，但**路由解析与域切换归外壳**，插件不自行处理协议。

**(3) 安全与边界**

- 快捷方式 / 深链只是**寻址指针，不含密钥、不含数据本体**：点开仍要解锁，仍受该域成员资格与域内身份约束，他人用这台设备点图标也进不去；
- **跨域不可关联**：链接与图标不携带"你加入了哪些组织"的可读清单，图标名 / 样式用户自定，并提示"该图标会出现在系统桌面、本机可见"；
- 退出某组织后，指向该域的固定入口**自动失效**，路由按当前成员资格判定、给"已无权访问"，不残留打开。

**(4) 与"独立 OS 原生窗口"的关系**：本节是"入口直达"，落点仍在主程序的应用内模拟窗口；Tauri 支持每应用开一个独立 OS 原生窗口（独立 Webview / 独立任务栏项），列为后续增强，不阻塞第一版快捷入口。手机端对应物见 [shell-mobile §3.4](shell-mobile.md)。

## 四、全局组件

- **全局搜索（Cmd/Ctrl+K）**：浮层搜索，分类给出 事务 / 人 / 域 / 文件，只搜元数据面，标明索引源；
- **全局新建（Cmd/Ctrl+N）**：在当前域上下文下新建——当前在某组织桌面则默认在该域发起事务 / 打开应用，避免发错域；
- **通知中心**：屏幕右上角聚合系统级通知，点击等价于走消息卡片深链；
- **快捷键**：⌘/Ctrl+1~4 切换四个一级入口，⌘/Ctrl+K 搜索，⌘/Ctrl+F 当前窗口内查找。

## 五、状态与诚实呈现清单（PC 端必须有）

| 状态 | 呈现位置 | 诚实文案要点 |
|---|---|---|
| P2P 直连 / 走中继 / 离线 | 左栏状态点（全局）＋ 空间上下文条右侧（当前空间，见 D3）；**不在窗口标题栏重复** | 走中继时说明中继只见密文 |
| 同步中 / 已同步 / 冲突 | 上下文条、文件应用 | 冲突保留双份、不静默覆盖 |
| 组织副本不足 K | 桌面角落 | "待其他成员上线补齐"，不假装已冗余 |
| 个人单副本 | 我的→个人数据 | 不承诺组织级"永不丢"，引导备份 |
| 决议 ≠ 已执行 | 事务详情、待执行分组 | 明确区分链上决议与链下执行回报 |
| 叶子模式（本机是手机时不在此列） | 设备与同步 | PC 默认完整副本，可手动设为只消费 |

## 六、设计决策记录（原待决问题，均已落定）

1. 左栏**默认展开 240px**，之后记忆用户的折叠 / 展开选择（§一）；
2. **第一版只做单桌面多窗口**，不做工作区 / 虚拟多桌面（一张空间桌面内不再分屏组）；
3. **不设同屏窗口硬上限、不自动关窗**，开几个由用户自己管理；仅在多 iframe 使内存吃紧时给一条非阻断性能提示，关不关仍由用户决定，配套用"非激活窗心跳降频 + `v-show` 保活"控开销；
4. 默认**应用内模拟窗口**（§3.5，ark 已验证）；第一版同时提供**系统级快捷入口 / 深链**（§3.7：系统快捷方式 + 链接唤起 + 浏览器/PWA），独立 OS 原生窗口列为后续增强。
