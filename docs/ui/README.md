# Spark 界面设计（UI）总纲

> 状态：草稿 v0.5（v0.3 事务形态归类型插件；v0.4 与操作系统衔接；v0.5 通讯录、公共议题归位为空间插件，外壳事务只聚合"与我相关"，身份切换归插件）
>
> 本篇是 Spark **产品层的界面设计说明**：讲清楚信息架构、四个一级入口装什么、PC 与手机两套外壳如何同构，不写像素级视觉稿。术语一律以 [产品全景](../product/product-map.md) 术语表为准。

## 〇、命名约定（先统一词汇，后文不再重复解释）

同一个东西在三个层面有三个名字，界面、文档、代码各用各的，互不打架：

| 层面 | 用词 | 例子 |
|---|---|---|
| **用户看到的入口与实体** | **空间** | 一级入口标签「空间」；个人空间、家庭空间、阳光小区空间 |
| **界面形态** | **桌面** | 点进某个空间看到的那张桌面（PC 多窗口 / 手机 App 网格） |
| **技术 / 文档术语** | **域（domain，域空间）** | 数据域边界、域身份、递归共同体 DAG |

一句话：**空间是用户看到的名字，桌面是它的样子，域是它的本质。** 对普通用户界面不出现"域"字；工程与产品文档保留"域"以精确表达边界。

## 一、一句话设计主张

**Spark 不是一堆功能页，而是一台"可安装的共同体操作系统"。** 界面因此借用操作系统的心智模型：

- **空间**是桌面（个人空间 + 每个组织各一张桌面），**插件是桌面上的应用**，PC 上以独立窗口打开、手机上以独立 App 打开；
- **消息**是全系统统一的收件箱；**事务**是全局任务中心；**我的**是这台机器的根身份与控制面板。

外壳（导航、桌面、窗口管理、收件箱、事务列表）是内核级的稳定骨架；插件视图是壳里可替换的内容——这正对应 [机制与政策分离](../product/product-map.md)：壳只提供中性容器，"这是什么、怎么呈现"由插件解释。

## 二、设计原则（全部由产品哲学推出，不可违背）

1. **外壳稳定、内容可换**：导航与窗口框架不认识任何具体业务；选举、账本、论坛都是插件在壳里渲染，卸载插件不动任何数据（见 [插件解释权](../product/plugins/README.md)）。
2. **当前域永远可见、跨域不串味**：你在哪个空间、以哪个身份操作，界面必须时刻明示；切换组织即切换身份、数据边界与已装插件，不允许一个界面里混入两个域的数据（承接 [身份三层](../product/foundation/identity.md)）。
3. **一次解锁、全域可达**：解锁根身份后切换任何已加入的组织空间都不再登录，但也绝不做"跨域一键关联身份"（[identity](../product/foundation/identity.md) 边界）。
4. **状态诚实、不假装**：同步中 / 单副本 / 离线 / 走中继 / 叶子模式 / "决议 ≠ 已执行" / 副本健康度，都如实呈现，不用绿色对勾制造"已万事大吉"的错觉。
5. **事务是一等公民，不被埋进某个组织**：因为事务"只有发起人、没有归属"（[affair-model](../product/affairs/affair-model.md)），它在导航里独立成一级入口，而不是藏在每个组织内部。
6. **消息只负责触达，处理回到本体**：消息里的一张卡片把你带到对应事务 / 插件，消息本身不成为第二个处理场所。
7. **双端同构、交互随俗**：PC 与手机是同一套信息架构与同一套概念，但 PC 用桌面多窗口、手机用微信式底栏 + 手机桌面，贴合各平台肌肉记忆。

## 三、信息架构：四个一级入口

```
                    ┌──────────────────────────────────────────┐
                    │              当前域上下文条               │
                    │  你是谁（当前身份） · 在哪个空间 · 同步状态 │
                    ├──────────────────────────────────────────┤
   PC：左侧常驻栏    │                                          │
   手机：底部 Tab    │              主工作区（随入口切换）        │
                    │                                          │
   ┌──────────┐     └──────────────────────────────────────────┘
   │ 我的     │  根身份 / 设备信任 / 我的数据与设置 / 个人资产入口
   │ 消息     │  统一收件箱：私聊 + 所有插件的应用会话卡片
   │ 空间     │  个人空间与各组织空间的"桌面"，插件即应用
   │ 事务     │  跨全部域的事务列表：要我处理 / 进行中 / 已决议
   └──────────┘
```

| 入口 | 回答的问题 | 对应产品层 | 内容来源 |
|---|---|---|---|
| **我的** | 我是谁、我的设备与数据、我的全局设置 | foundation 底座 | 根身份、设备信任、个人域数据 |
| **消息** | 有什么在找我、谁对我说了什么 | community 通信底座 | 统一 DM 底座 + 插件投递 |
| **空间** | 我此刻在哪个"地方"干活、用哪些应用 | 四层都在此发生 | 当前域 + 该域已装插件 |
| **事务** | 有哪些共同决定等我 / 我发起 / 我关注 | affairs（贯穿 economy） | 我持有副本或有资格的全部事务 |

> 为什么不更多：**通讯录、公共议题都是"空间"里的插件应用，不挂进其它入口当固定页签**——通讯录（个人好友 / 组织成员）在各自空间作为插件打开，公共议题是可浏览发现的插件。**应用市场则按三动作模型拆成两层**（[install-and-enable](../product/plugins/install-and-enable.md)）："拿到代码 / 装卸 / 更新"是本机系统层动作，收在系统级应用管理里（PC 左栏「应用管理」对话框、手机底 Tab「应用」，见 L4/M4）；空间桌面侧的市场入口语义只是"为本空间启用"，只在往当前空间桌面加应用时需要。**一级导航只留无法被任何插件替代的事。**

## 四、四个入口的内容模型（平台无关）

### 4.1 我的：根身份与控制面板

"我的"与具体组织无关，是这台设备与你根身份的家：

- **身份与安全**：根身份状态、改密码、助记词与加密二维码备份、生物识别设置、7 天密码提醒、登录设备列表与撤销、延迟恢复（[identity](../product/foundation/identity.md)）；
- **设备与同步**：已配对设备、本机是"完整副本"还是"叶子模式"、各设备在线状态、同步与中继状态（[network](../product/foundation/network.md)）；
- **个人数据**：存储占用、备份与导出、删除语义说明、整体导出包（[personal-data](../product/foundation/personal-data.md)）；
- **我的组织**：我加入的全部叶组织 / 我相关的共同体列表（点击即切换到对应空间，不在此处理内部事务）；
- **个人资产入口**：我在各组织的积分账户列表（积分记名、分组织列示，不做跨组织合并余额，见 [credits](../product/economy/credits.md)）、我的公开履历（只载可验证事实、无信用分）；
- **设置**：通知与免打扰（本机）、外观、语言、网络与中继偏好、关于与版本、独立核验工具入口。

### 4.2 消息：全系统统一收件箱

内核只有一条端到端 DM 通道，**所有"来找你"的东西都在此聚合**（[communication](../product/community/communication.md)）。它更像操作系统的**通知收件箱**而非聊天工具：会话流里既有私聊，也有系统通知与各插件的应用会话卡片；空态等文案一律按「通知 / 消息」口径，不写「聊天」限定语。

- **两类会话并列**：
  1. **私聊会话**：人与人（含自己的其他设备），由默认聊天插件或第三方聊天插件呈现；
  2. **应用会话 / 服务号**：每个业务插件一个会话，内容是结构化**卡片**——组织邀请、好友申请、表决邀请、积分到账 / 兑付、公告、流程待办、交付佐证请求；
- **一张卡片 = 一个深链**：点"表决邀请"卡片跳到对应事务详情，点"积分到账"跳到该组织积分应用，处理动作回到本体完成，消息里只留结果回执；
- 消息**只有会话流、不内嵌通讯录**：通讯录是各空间里的插件应用（个人空间＝个人好友、组织空间＝组织成员，两套人脉仍分开，见 [communication](../product/community/communication.md)）；发起新会话靠顶部搜索 / `＋` 拉起选人，不常驻通讯录页签；
- 未读角标、免打扰是**每台设备本地**设置；消息状态（发送中 / 已送达 / 已读）如实显示，离线暂存有 TTL 时给出"对方离线、待投递"的诚实提示。

### 4.3 空间：干活的桌面（详见 [domain-space.md](domain-space.md)）

进入后先选定"我在哪个域"：一个**个人空间** + 我加入的每个组织各一张桌面。桌面上摆该域可用的插件图标；PC 多窗口、手机全屏 App。它是唯一承载"具体干活界面"的入口，其余三个入口都是跨域的全局视图。

### 4.4 事务：全局事务列表

跨所有域、**只聚合"与我相关"**的事务：要我表决 / 我发起 / 我关注 / 我有资格但未关注。**公共浏览 / 发现不占外壳页签**——"公共议题"是空间里的一个插件应用（去中心化公共发现面，只检索标题 / 简介 / 标签三元数据，见 [public-topics](../product/affairs/public-topics.md)），想看就去打开该插件，外壳事务入口不混入"与我无关"的洪流。空间内某插件也可有"本域事务墙"，与全局列表数据同源、只是过滤范围不同。

**筛选与分组维度**（可组合）：

| 维度 | 取值 |
|---|---|
| 处理状态 | 要我操作（高亮）· 进行中 · 待执行（决议已出、链下未完成）· 已决议关闭 · 已中止 / 过期 |
| 所属域 | 全部 · 某组织 · 公共事务（事务本身无归属，这里按"效力锚定的域 / 我的资格来源域"过滤） |
| 事务类型 | 由类型插件提供：选举 / 预算 / 签名表决 / 讨论 / 项目议题……（类型清单动态来自已装插件，壳不写死） |
| 时间 | 公示中 · 即将截止 · 已超期未达标 |
| 我的参与身份 | 上下文身份 · 公共身份 |
| 谱系 | 父子 / 申诉 / 继承关系（点进详情看谱系图，列表只标小图标） |

列表每条事务卡片显示容器级元数据与内核求值结果：标题、所属域、类型、当前状态、通过进度（已投 / 法定人数快照）、截止倒计时、我是否已投。**"等我操作"永远排在最前**，这是事务入口存在的首要价值。

> **列表归外壳，单个事务归插件。** 点击任一事务项，外壳按它的**类型标识**打开对应的**事务类型插件**视图（PC 开成窗口、手机开成全屏 App）——选举长什么样、预算怎么展示、讨论如何排布，全部由该类型插件决定，**外壳不提供统一"事务详情页"、不规定内部骨架**。这与"插件即应用"同一心智：类型插件就是某类事务的"默认打开程序"；若本机没装能处理该类型的插件，外壳给"去系统级应用管理安装对应插件"的空状态（如同系统没有能打开某类文件的程序）；已安装但**未在该空间启用**时则引导去启用——拿到代码与启用是两个动作，空状态分开说。类型插件必须遵守的通用硬约束（资格不符不放投票入口、时间以存证链为准、公共身份永久公开提示、决议≠已执行、关注=持有副本）属于**插件层呈现契约**，不由 UI 外壳规定（见 [plugins/](../product/plugins/README.md)，落地项登记在第八节）。

## 五、PC 与手机：同构的两套外壳

| | PC（[shell-desktop.md](shell-desktop.md)） | 手机（[shell-mobile.md](shell-mobile.md)） |
|---|---|---|
| 一级导航位置 | 左侧常驻竖栏 | 底部 Tab 栏（微信式） |
| 一级顺序 | **我的 · 消息 · 空间 · 事务**（自上而下） | **消息 · 空间 · 事务 · 我的**（"我的"固定在最右第四位） |
| 空间形态 | 操作系统桌面，插件开成可层叠 / 并排的**独立窗口** | 手机系统桌面，插件点开是**全屏 App**，卡片式多任务切换 |
| 多任务 | 多窗口同屏并排（边看账本边讨论） | 最近应用卡片栈，一次一个全屏 |
| 主导手势 | 鼠标 / 键盘、拖拽、多窗 | 拇指：底栏切换、左滑返回、下拉 |
| 典型工作姿态 | 长时间、多窗、重处理（开票、计票、对账） | 碎片、快速响应（收到表决、随手投、看通知） |

> 两端数据、身份、事务状态完全同源；手机默认是**叶子模式**（只消费、不对外提供副本），在"我的→设备与同步"里可自查。

## 六、全局通用机制

### 6.1 当前域上下文条

主工作区顶部始终有一条轻量上下文条：`当前身份昵称（域内名） · 空间名称 · 同步/在线状态`。它是原则 2、3 的落点：任何时候用户都知道"我现在是谁、在哪个组织里动作"；从消息卡片深链进入某组织事务时，上下文条随之切到该域，避免误操作到错误空间。

### 6.2 通知 → 本体的跳转

所有需要行动的事都先以卡片到达"消息"，点击统一跳到本体（事务详情 / 某空间某插件窗口）；本体处理完回写一张结果卡片。**不在通知里做会产生效力的动作**（投票、兑付、批准一律进本体二次确认），防止在信息不全处误操作。

### 6.3 插件视图容器

桌面图标、窗口、App 页都是插件视图的运行容器，提供统一的：标题栏 / 加载 / 空状态 / 错误与离线态 / 权限申请提示（插件要读哪些域数据）/ 信任级标识（L0/L1/L2，见 [runtime-and-trust](../product/plugins/runtime-and-trust.md)）。插件崩了只关这个窗口，不拖垮外壳。**从事务列表点进的单个事务也是一种插件视图**：外壳只负责"按类型找到并打开对应插件、把它装进容器"，容器内的全部布局与交互归插件（见 §4.4）。

### 6.4 全局搜索

只搜元数据面（标题 / 简介 / 标签）与人 / 域 / 文件名；内容面（正文、附件）按需拉取（[affair-model](../product/affairs/affair-model.md)）。搜索结果按"事务 / 人 / 空间 / 文件"分类，来源 indexer 可切换、排序是确定性函数，界面上标明当前索引源。

### 6.5 空状态与首次进入

- 全新用户：没有组织时，空间里只有一张"个人空间"桌面，引导创建第一个叶组织（家庭）或加入组织；
- 空组织桌面：引导从应用市场装第一批插件、发起第一个事务；
- 所有空状态都给"这是什么 + 下一步"，不留下空白页。

### 6.6 与操作系统衔接（深链是统一底座）

Spark 不把用户关在应用内，提供三类与底层系统（Windows/macOS/Linux、Android/iOS）衔接的能力，规则双端一致：

- **文件互拖 / 系统分享**：PC 可从系统文件管理器把文件 / 文件夹拖进某空间（拖入摄取、落点即域、进组织域前明示可见范围），也可把域文件拖出到系统（导出为脱离域保护的明文副本并提示）；手机用系统"分享 / 打开方式"完成等价导入（[shell-desktop §3.6](shell-desktop.md)）；
- **系统级快捷入口 / 深链**：可把一张空间、一个应用或一个对象固定成系统桌面 / 主屏幕图标，或复制 `spark://` 深链；点击经**单实例**唤起客户端并"先切域再开目标"。快捷方式只是寻址指针、不含密钥与数据，仍需解锁、受成员资格约束，退出组织即失效；浏览器 / PWA 仅作受限只读与唤起引导，完整体验以客户端为准（[shell-desktop §3.7](shell-desktop.md)、[shell-mobile §3.4](shell-mobile.md)）；
- 消息卡片、事务、通知、系统快捷入口**共用同一条深链路由**，全系统只有一套"跳到本体"的寻址逻辑（落地见 [ui-architecture §4.4/§4.7](ui-architecture.md)）。

## 八、设计决策记录（原待决问题，均已落定）

1. **通讯录是空间插件、不进消息页签**（v0.5）：个人好友 / 组织成员两套人脉在各自空间的通讯录插件里分开，消息只留会话流；
2. **公共议题是空间插件、不占事务页签**（v0.5）：外壳事务列表只聚合"与我相关"，公共发现由公共议题插件承担；
