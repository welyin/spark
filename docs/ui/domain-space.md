# 空间（内部称"域"）：把每个域做成一张桌面

> 状态：草稿 v0.4 ｜ 分册：UI 设计（v0.4 落定跨域拖拽确认强度，新增"从操作系统拖入"的进入规则）
>
> **命名三层**：对外入口与实体叫**「空间」**（个人空间、家庭空间、阳光小区空间）；它的界面形态叫**「桌面」**；技术 / 文档术语仍叫**「域（domain）」**——空间是用户看到的名字，桌面是它的样子，域是它的本质。
>
> 本篇定义 Spark 最核心的界面隐喻：个人空间与每个组织各是一张独立桌面，插件是桌面上的应用。PC 窗口与手机 App 的平台差异分别见 [shell-desktop](shell-desktop.md) / [shell-mobile](shell-mobile.md)，本篇只讲与平台无关的空间模型。上游概念：[递归共同体模型](../product/community/model.md)、[插件类型](../product/plugins/plugin-types.md)。

## 一、为什么用"桌面"隐喻

用户已经被操作系统教会了一件事：**桌面上的图标是应用，应用在窗口里打开、各干各的、互不干扰。** Spark 直接复用这套心智：

- 一个**域**（个人空间 / 家庭 / 摄影小组 / 楼栋 / 小区）= 一台独立电脑的一张桌面；
- 一个**应用视图插件** = 一个应用程序，桌面上有图标、点开有窗口 / App；
- 同一个"文件"应用在不同域打开，看到的是**不同域的数据**——个人桌面看到私人文件，家庭桌面看到家庭共享文件。插件只是查看器，数据属于域、不属于插件（[catalog](../product/plugins/catalog.md)）。

于是"切换组织"在体验上等于"切换到另一台电脑的桌面"：壁纸 / 图标 / 打开的应用 / 你的身份全都换了一套，边界天然清晰——这正是"跨域不串味"原则的可视化。

## 二、空间的种类与唯一成员规则的界面表达

| 空间 | 是不是组织 | 桌面上有谁的数据 | 典型默认应用 |
|---|---|---|---|
| **个人空间** | 不是组织，纯私域 | 只有自己 | 文件、相册、AI 助手、朋友圈、个人笔记 |
| **叶组织空间** | 组织，成员是个人 | 全体成员 | 事务、账本、表决、文件、公告、会议、聊天群 |
| **共同体空间（共同体域）** | 组织，成员只能是组织 | 各成员组织（按"户"） | 选举、公共账本、信息公示、监督审计、成员组织名册 |

- 个人空间永远排在域列表第一位、且不可删除 / 退出；
- 共同体域的界面语言是"成员组织 / 按户"，叶组织是"成员个人"，**不出现与结构不符的措辞**（例如不在小区域显示"添加个人好友"）；
- 层级关系（个人→家庭→楼栋→小区）可在域切换器里用可折叠树辅助理解，但**每个空间在导航里是平权的**——上级桌面不天然包含、也不能命令下级桌面，呼应"层级不产生权力"。

## 三、域切换器（space switcher）

进入"空间"后的第一个控件（内部称域切换器），回答"我现在要去哪张桌面"：

- 顶部：**个人空间**固定置顶；
- 下方默认形态是**列表 + 搜索**：按"最近使用"排序列出我加入的叶组织与共同体域，搜索框常驻、输入即按名称过滤——域很多时主要靠搜索定位、不靠翻找；不默认铺 DAG 树，仅在需要看清上下级归属时提供"按层级树查看"的辅助切换；
- 每个域条目显示：域头像 / 名称 / 我的域内身份昵称 / 未处理事务数小角标 / 副本与同步状态小图标；
- 底部固定入口：`＋ 创建组织`、`加入组织`（走邀请 / 认领流程，见 [membership](../product/community/membership.md)）；
- **切换即换上下文**：切到某域后，顶部上下文条、桌面图标、已开窗口、当前身份全部切到该域；最近一次所在域被记住，下次回到「空间」时回到这张桌面。**不提供"把某张组织桌面钉为开机默认"**——高频入口是消息与事务（常由它们的深链直接带进对应空间），空间桌面本身不需要固定开机落点；

> 跨域不可关联：切换器只列"我"的域，不向任何域暴露我还加入了哪些别的组织；在某域内显示的昵称 / 头像用该域专属身份，不用个人资料（除非该域显式选用个人身份）。

## 四、桌面上摆什么：插件即应用

### 4.1 应用图标从哪来：拿到代码 ≠ 启用（三动作模型）

一个插件能不能出现在某张桌面，由两个权责不同的动作共同决定（完整模型见 [install-and-enable](../product/plugins/install-and-enable.md)）：

| 动作 | 是什么 | 作用层 | 谁的动作 |
|---|---|---|---|
| **安装到本机（拿到代码）** | 把插件包下载 / 侧载到本机 | **系统层**（本机），与任何空间无关 | 个人，自由 |
| **在某空间启用** | 把本机已有的插件挂到一个具体空间、实例化运行 | **空间层**，作用域永远是单个空间 | 个人空间＝我自己；组织空间＝组织（规则 / 立法类须走组织事务、集体决议；纯视图 / 工具类由组织策略自定，可放权成员本地自选） |

- 桌面图标的完整条件是"**本机已安装 ∧ 当前空间已启用**"；同一插件可在多个空间分别启用、各自配置，启用后的实例按空间隔离（家庭账本和小组账本互不影响）；
- 应用市场本身是一个内置应用，负责发现 / 安装 / 更新（即"拿到代码"这一系统层动作），并显示安装通路信任级 L0/L1/L2（[runtime-and-trust](../product/plugins/runtime-and-trust.md)）；验证类插件必须 ≥ L1，L0 侧载在界面上直接置灰并说明原因。**在某张空间桌面里打开市场，语义是"为本空间挑选并启用"，安装动作仍在系统层完成**；
- **卸载 / 停用 / 替换都不碰数据**：卸载＝本机系统层删掉插件代码（**仅移出本机**，不存在"组织卸载"，组织空间的卸载同样只影响本机）；空间层的对应动作是**停用**——把该实例从这张桌面撤下，数据原样保留；换一个同类插件打开，旧数据仍在——卸载确认弹窗里明确写"仅移出本机、不删数据"，消除"会不会丢东西"的顾虑；
- 组织"启用了什么"的目标形态是随**组织启用清单**同步给全体成员（见 [install-and-enable §五](../product/plugins/install-and-enable.md)）；**过渡期内核尚未支持清单走组织副本，启用事实存本机，界面如实标注"仅本机生效，成员同步待内核"**，接口按未来的内核清单设计。

### 4.2 默认桌面（第一版建议的出厂图标）

不同空间的默认图标不同，全部来自 [catalog](../product/plugins/catalog.md) 的内置应用与里程碑插件，壳不内置业务：

- **个人空间**：文件、相册、聊天、通讯录、AI 助手、朋友圈、应用市场；
- **叶组织**：事务墙、文件、群聊、公告、任务看板、（里程碑二）账本 / 表决 / 会议；
- **共同体域**：签名表决、选举、公共账本、信息公示、成员组织名册、监督审计。

> 事务墙（spark-affairs）是**事务类型插件**，典型适用域＝组织域（解释"集体如何共同决定"，个人空间没有第二人、不构成集体事务，见 [install-and-enable §三](../product/plugins/install-and-enable.md)），因此只出现在组织空间的默认桌面，个人空间默认图标不含它。

默认图标可删可换；缺什么由应用市场补。

**桌面排布定稿为"组织只给默认布局、成员本地各自排布"**：组织下发的只是上面这份默认图标清单与默认顺序；每位成员怎么摆图标、建什么文件夹、固定哪些到任务栏 / Dock，全部存在本机、只对自己生效——成员之间互不可见、互不影响，也不跨设备同步（本地持久化结构见 [shell-desktop §3.5(4)](shell-desktop.md)）。组织（含管理员）不能统一定制成员桌面，避免再长出一个管控点；壁纸 / 主题色同理，组织可给"建议默认"，用不用由成员本地决定（PC 自由摆放、手机分页与文件夹）。

### 4.3 应用窗口 / App 的统一外壳

每个插件打开后都套一层统一容器，容器由外壳提供、插件只填内容：

- 标题区：应用名 + 当前域 + 信任级小标 + 权限状态；
- 标准态：加载中 / 空 / 离线（P2P 暂不可达、是否走中继的选择）/ 错误，且**单插件崩溃只关自己**；
- 能力申请：插件首次要读某类域数据 / 要发消息卡片时，统一弹授权说明，用户清楚"它能碰到什么"；
- 应用内产生的待办 / 通知，不自己弹角标，统一投递到"消息"，保证全系统只有一个收件箱。

## 五、桌面与数据边界（界面如何"看得见边界"）

1. **视觉区隔**：每张桌面可有独立主题色 / 壁纸 / 域名水印，让用户一眼分辨"我在家庭还是在小区"，高危域（管钱、管选举）视觉上更郑重；
2. **数据不外溢**：任何应用的"分享 / 发送"都要显式选目标域或联系人，**不存在"一键同步到所有组织"**。**PC 跨窗口拖拽**指：在多窗口桌面上，用鼠标把**属于 A 域的对象**（文件 / 图片 / 事务卡片 / 账本条目 / 人选等）拖进**B 域应用的窗口**（如把个人空间的照片拖进某组织群聊）。**同一空间内**窗口互拖不打断、不弹确认；**源对象与目标窗口一旦分属不同域**，松手时弹目标域确认（明确显示"将把『X 域的对象』发送到『Y 域』"，可取消）；手机端用系统分享面板完成等价动作。**确认强度定稿**：每次跨域都弹目标域确认，确认框提供勾选项"本次会话内，同一 源域→目标域 不再提示"（仅本次运行有效、关闭即失效，不做永久豁免）；同一空间内拖拽永不弹；
3. **组织数据的副本状态可见**：组织桌面角落显示该域当前在线数据节点数 / K 副本健康度；单机在线、副本不足时给非焦虑式提示（"当前只有你的设备在线，数据待其他成员上线后补齐副本"）；
4. **个人空间诚实标注**：个人空间是单副本 / 靠自有设备互为备份，界面不承诺"组织级 K 副本永不丢"，并在备份处引导设备信任与导出（[personal-data](../product/foundation/personal-data.md)）；
5. **从系统外导入（OS → 域，方向与内部跨域相反）**：支持把操作系统文件管理器里的文件 / 文件夹直接拖进某张空间桌面或其应用窗口，这是数据**进入** Spark 的入口（ingest）。**落点即域**——拖到哪个域的窗口 / 桌面 / 导航项就进哪个域，拖拽全程高亮目标域名称与可见范围（个人空间＝仅自己、叶组织＝全体成员、共同体＝成员组织）。拖入个人空间是纯私有摄取、不打断；**拖入组织域等于对外发布、会随副本同步给成员，松手前必须明示**。外部文件统一归域存储、不归属任何插件；外壳只把"被拖中的这几个文件"的最小读取句柄交给目标插件，不授予整盘访问，可执行 / 不支持类型与超大文件给风险提示且不自动运行。PC 交互见 [shell-desktop §3.6](shell-desktop.md)，手机端用系统分享 Sheet 选目标域完成等价导入。

## 六、跨端差异（只列结论，细节进各外壳分册）

| | PC 桌面 | 手机桌面 |
|---|---|---|
| 布局 | 图标 + 可自由层叠 / 贴边并排的多窗口，可同屏开多个应用 | 图标网格 / 分页 / 文件夹，点开全屏单 App |
| 多任务 | 窗口常驻、任务栏列出已开应用 | 最近应用卡片栈，上滑关闭、点击回到前台 |
| 跨窗口协作 | 支持把事务卡片 / 文件拖到聊天窗口等跨窗操作 | 用系统级分享面板完成等价动作 |
| 后台 | 窗口可最小化到任务栏继续收通知 | 叶子模式，切到后台靠推送触达 |

## 七、设计决策记录（原待决问题，均已落定）

- 域切换器默认形态 ＝ **列表 + 搜索**（最近使用排序、搜索框常驻），DAG 树仅作可选辅助（§三）；
- 桌面排布 ＝ **组织只给默认布局、成员本地各自排布、存本机不跨端、组织不统管**（§4.2）；
- **不做**"钉某张组织桌面为开机默认"，进入空间回到最近一次桌面，高频走消息 / 事务深链直达（§三）；
- 内部跨域拖拽：每次弹目标域确认、可"仅本次会话、同一 源→目标 路径豁免"（关闭即失效）、同域不弹（§五.2）；
- 支持**从操作系统拖入**文件 / 文件夹：落点即域、导入组织域前明示可见范围、只授被拖文件的最小句柄（§五.5、shell-desktop §3.6）。
