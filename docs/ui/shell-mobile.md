# 手机端外壳：微信式底栏 + 手机桌面

> 状态：草稿 v0.3 ｜ 分册：UI 设计（v0.2 §3.4 主屏幕快捷入口；v0.3 通讯录/公共议题归位空间插件，重写弱网入队与推送策略）
>
> 本篇定义手机端布局与交互。信息架构与内容模型见 [README](README.md)，空间桌面模型见 [domain-space.md](domain-space.md)，PC 对应物见 [shell-desktop.md](shell-desktop.md)。**命名约定**：底部 Tab 对外标签为「空间」（内部称域空间 / 域）。手机默认是**叶子模式**（只消费、不对外提供副本，见 [network](../product/foundation/network.md)），交互追求碎片时间的快速响应。

## 一、整体布局：底部五个 Tab

沿用主流 IM（微信）的拇指肌肉记忆：底部固定五 Tab，顺序为 **消息 · 事务 · 空间 · 应用 · 设置**（M4/M9 已定稿并实现；第五位原名"我的"，M9 改名"设置"，原"我的"内容全部收进其"个人设置"）。

```
┌───────────────────────────┐
│                           │
│                           │
│        当前 Tab 页面       │
│      （全屏，顶部导航栏）   │
│                           │
│                           │
├───────────────────────────┤
│ 消息   事务  空间  应用  设置│
│ 〔3〕                      │
└───────────────────────────┘
   ↑ 角标：消息=未读，事务=等我操作
```

- 五 Tab 与 PC 左栏入口对应：PC 的「应用管理」是 rail 顶级对话框（L4），手机不适合弹窗、升格为底 Tab「应用」（M4）；「我的」不占 Tab，内容并入「设置」的个人设置（M9）；
- 角标规则同 PC：消息=未读会话数，事务=**等我操作**数；
- 顶部导航栏随 Tab 变化：标题 + 该页搜索 / 加号 / 更多；
- 通讯录、公共议题都是"空间"里的插件应用（不挂进消息 / 事务当固定页签）；**「应用」Tab＝系统层应用管理**：列出整个系统已安装的全部应用（跨所有空间、不按空间分），统一在此安装 / 卸载 / 更新（"拿到代码"是本机系统层动作），"在哪些空间启用"进该应用的详情页（空间层）；空间桌面内的市场入口语义是"为本空间启用"，不是往本机装代码（[install-and-enable](../product/plugins/install-and-enable.md)）。

## 二、消息 Tab（对标微信首页）

```
┌───────────────────────────┐
│ 消息            🔍  ＋     │
├───────────────────────────┤
│ 〔服务号〕业委会·待你表决 › │
│ 家庭群              10:24 ›│
│ 〔服务号〕积分·本月到账    ›│
│ 张三                昨天  ›│
└───────────────────────────┘
```

- 会话列表与微信一致：私聊、群聊（聊天插件）、**服务号（应用会话）**混排或分组；服务号用插件图标 + 标签前缀区分；
- 点私聊进聊天页（由聊天插件渲染，可替换、数据不变）；点服务号进卡片流；
- 卡片上的行动按钮（去表决 / 接受邀请 / 查看兑付）**深链跳到对应本体页**，不在消息里直接生效；
- 顶部右上：`＋`（发起私聊 / 加好友 / 扫一扫，拉起选人）、搜索；**不内嵌通讯录**——通讯录是空间插件（个人好友 / 组织成员两套人脉在各自空间分开）。

## 三、空间 Tab：一张"手机系统桌面"

这是手机端最关键的隐喻：**点进"空间"，就像进入了一台只属于当前域的手机桌面。**

### 3.1 两级结构

```
第一级：域列表（"我的手机桌面列表"）        第二级：某域桌面（手机桌面）
┌───────────────────────────┐          ┌───────────────────────────┐
│ 空间              🔍  ＋   │          │ ‹ 家庭      〔切换域〕 ▾   │
├───────────────────────────┤          ├───────────────────────────┤
│ 👤 个人空间               ›│          │  [文件] [相册] [群聊]      │
│ 🏠 家庭            〔2〕  ›│          │  [账本] [表决] [公告]      │
│ 🏘 阳光小区        〔1〕  ›│          │  [会议] [任务] [市场]      │
│ 📷 摄影小组              ›│          │                           │
└───────────────────────────┘          │     （图标网格/分页/文件夹）│
                                        └───────────────────────────┘
```

- 第一级：个人空间置顶，其下是我加入的域，带待办角标；`＋`创建 / 加入组织；
- 第二级：该域的**手机桌面**——应用图标网格、可分页、可拖入文件夹，完全复刻手机操作系统桌面的交互；点图标**全屏打开一个 App（插件）**。

### 3.2 应用 = 全屏 App + 卡片式多任务

- 一个插件打开就是一个全屏页面，顶部是统一 App 导航栏：`‹ 返回桌面` · 应用名 · 当前域 · 更多；
- 多任务：从桌面底部上滑 / 双击调出**最近应用卡片栈**（同 iOS/安卓最近任务），左右滑切换、上滑关闭；一次只与一个全屏应用交互；
- 需要对照两个应用时（如边看账本边投票），用"在事务中引用 / 应用间跳转"代替 PC 的并排窗口；
- App 内待办统一投递给"消息"，不自己悬浮角标；从消息深链回来时直接定位到对应域桌面并打开该 App。

### 3.3 安装与桌面编辑

- 桌面长按进编辑模式：抖动、可拖动 / 删快捷方式 / 建文件夹；"添加应用"进应用市场——语义是**为本空间启用**（从本机已装插件挑选挂到当前空间，未装的可先拿到代码；组织空间规则类走事务立法、视图类走该域组织策略）；
- 卸载弹"只移除应用、不删除该域数据"说明；信任级 L0/L1/L2 在应用详情页标明，验证类 L0 直接置灰（[runtime-and-trust](../product/plugins/runtime-and-trust.md)）。

### 3.4 投射到系统主屏幕：快捷入口（对应 PC §3.7）

支持把一张空间 / 一个应用 / 一个对象固定成手机系统层面的直达入口：

- **Android**：应用内"添加到主屏幕"→ 由系统 pin 出直达图标，点击唤起 App 并路由到目标空间 / 应用；长按 Spark 应用图标列出常用空间 / 应用的动态快捷方式；
- **iOS**：系统不允许 App 静默往主屏幕加图标，走"Safari 分享 → 添加到主屏幕"（Web Clip，带深链）或"快捷指令"App 由用户手动添加；长按主屏幕 App 图标用 Quick Actions 列常用项；
- **深链唤起**：`spark://…` 与 Universal/App Link（https）点击直接唤起已安装 App 并路由、不进浏览器，未安装落到 web 引导页；
- 安全边界同 PC：快捷方式只是寻址指针、不含密钥与数据，点开仍需解锁（叠加每 7 天强制密码）、受成员资格约束，退出组织后入口失效；图标本机可见、名称可自定，不暴露完整域清单。

## 四、事务 Tab（快速处理优先）

手机端的核心场景是"收到表决、随手投掉"，因此列表比 PC 更强调**立即行动**。

```
┌───────────────────────────┐
│ 事务    〔只看与我相关〕 ⌄  │
├───────────────────────────┤
│ ▌等我操作（2）             │
│  是否动用公共收益修电梯     │
│  阳光小区·签名表决  剩 1 天 │
│  已投 18/24        〔去投›〕│
│ ───────────────────────── │
│ ▌进行中                   │
│  秋季出游预算              │
│  摄影小组·预算      剩 3 天 │
└───────────────────────────┘
```

- "等我操作"置顶、每条直接带`去处理`大按钮；
- 事务列表**只看与我相关**（无"公共"页签——公共议题是空间里的插件应用）；筛选（状态 / 域 / 类型 / 时间 / 参与身份）收进一个筛选抽屉，默认只留最常用的"域"chips；
- **点卡片不在外壳开统一详情页，而是按事务类型打开对应类型插件的全屏 App 页**（走 §3.2 的 App 容器与最近任务栈）：页面结构、投票操作条、日志 / 谱系怎么排全由该插件决定；本机未装该类型插件时引导去「应用」Tab（系统层应用管理）安装（拿到代码）；已装但**未在对应空间启用**时引导去启用——两个动作分开说；
- 身份二次确认、时间权威、资格判定等是**类型插件必须遵守的呈现契约**（见 [README §4.4](README.md)），外壳不替它画操作条。

## 五、我的 Tab（对标微信"我"）

```
┌───────────────────────────┐
│ 我                         │
│ 〔头像〕根身份昵称  身份卡 ›│
├───────────────────────────┤
│ 🔐 账号与安全（密码/助记词）›│
│ 💻 设备与同步（本机=叶子） ›│
│ 🗂 个人数据（存储/备份/导出）›│
│ 🏛 我的组织               ›│
│ 🪙 我的积分（分组织列示）   ›│
│ 🔔 通知与免打扰           ›│
│ ⚙ 设置 / 独立核验工具 / 关于›│
└───────────────────────────┘
```

- 高危操作（改密、助记词、撤销设备）必须输密码，生物识别不可用于此（[identity](../product/foundation/identity.md)）；
- **每 7 天强制输一次密码**的提醒在此承接；日常指纹 / 人脸解锁不变；
- "设备与同步"明确标注本机是叶子模式：组织数据只是暂存缓存、不对外提供副本，并给"在哪台设备上有完整副本"的列表。

## 六、推送、离线与叶子模式的手机特有处理

- **第一版不做系统通知栏推送**（不接 APNs / FCM / 国产厂商通道）：App 被杀或在后台时**收不到实时提醒**，只有 App 在前台 / 被打开时才经 P2P 收取；界面与"我的"处如实说明这一限制，不假装能实时触达。经第三方系统通道投递"不含正文的最小提醒"留作**远期可选插件**评估（非内核承诺，见 [network](../product/foundation/network.md)），不在第一版；
- 对方 / 网关离线时显示"待投递、上线后送达"，不假装已读；
- 弱网 / 离线：已缓存的桌面与事务可只读浏览；**操作在当下即用本机私钥签名并入本地队列，联网后自动补发、不要求二次确认**（尊重离线时的意愿，不因网络剥夺表达权），状态全程标"待发送 → 已上链"；若补发时发现已截止 / 资格不符 / 已达标，**不静默丢弃**，给一张"未被接受及原因"的明确回执；
- 手机不承诺承载组织 K 副本，副本健康度在"我的→设备与同步"里说明，避免用户误以为手机就是可靠备份。

## 七、手势与导航约定

| 手势 | 行为 |
|---|---|
| 底部点 Tab | 切换五入口；再点一次当前 Tab 回到该页顶部 / 刷新 |
| 屏幕左边缘右滑 | 返回上一级（App 内 → 域桌面 → 域列表 → Tab） |
| 域桌面底部上滑 | 最近应用卡片栈 |
| 长按应用图标 | 桌面编辑 / 快捷动作 / 添加到主屏幕（§3.4） |
| 下拉列表 | 刷新 / 同步 |
| 长按消息 / 事务条目 | 转发、收藏、引用发起事务等次级动作 |

## 八、设计决策记录（原待决，均已落定）

1. 一级入口命名：对外「空间」、界面「桌面」、技术「域」（见 README 命名约定）；
2. **不做**手机系统小组件（widget）；
3. 弱网 / 离线操作**当下即签名入队、联网自动补发、不二次确认**，以"待发送 / 已上链 / 未被接受及原因"的全程状态与回执兜底（见 §六）；
4. **第一版不做系统通知栏推送**（不接 APNs / FCM / 厂商通道），仅前台 / 打开时经 P2P 收取并如实告知限制；第三方通道最小提醒留作远期可选插件评估。
